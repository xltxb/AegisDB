# AegisDB 数据库管理网关

面向 DBA 与运维团队的统一数据库访问网关：所有数据库操作经 Web 终端 / 脚本 / 异步任务 /
数据导出 / 发布流水线 / 开放接口下发，由网关**逐语句实时判定** —— 放行、拦截或转审批；
审批通过后由**发起人自己**执行（见 ADR 0010）。全程写入防篡改审计哈希链，可经 Webhook /
飞书外推。支持真实连接 MySQL、PostgreSQL、Oracle、SQLite 等多引擎实例。

```
db-gateway/
├─ backend/     Go + Gin + GORM 后端（REST + WebSocket；风险引擎/RBAC/审批/审计哈希链/多引擎真实执行）
├─ frontend/    Vue 3 + TS + Vite 前端（Vela 设计系统，明暗双主题，中英双语，xterm.js 真终端）
├─ docs/        PRD / 前后端开发文档 / 交互原型 / ADR / 四份数据库规范 / 外部审批与开放接口对接指南
├─ deploy/      systemd unit + 环境变量模板
└─ docker-compose.yml  本地 MySQL 8 + Redis 7（可选）
```

## 功能总览

控制台共 16 页：总览 · 终端 · 导出 · 上传 · 后台执行 · 发布 · 流程 · 审查 · 审批 · 项目 ·
配置 · 规则 · 分层 · 权限 · 审计 · 设置。每页由菜单开关按角色收敛。

### 风险判定 · 环境/分层模型

- 判定链：`菜单权限 → 能力矩阵(角色×能力×分层) → 高危命令字典(命令×分层) → 无 WHERE 拦截(分层)`。
  四层规则**都按分层存**：最后一层拦截不带 WHERE 的 DELETE/UPDATE，2026-09 前它是一个全局开关，
  于是无法只对 dev 关掉（迁移 0030 起改为按分层，开关在【分层】页）。EXPLAIN 独立成档：`EXPLAIN` 只看计划、按只读判；
  而**会真的执行**被包住语句的那些形式按真实执行判 —— `EXPLAIN ANALYZE`／英式拼写
  `ANALYSE`、选项表里的 `(ANALYZE …)`、以及 DWS/GaussDB 的 `EXPLAIN PERFORMANCE`。
- **分层标签（tier）承载规则，环境（environment）归属实例**：内置五个分层 —— `prod` 生产、
  `gli` 法务、`staging` 预发布、`uat` 演练、`dev` 开发；可自建环境并挂到任一分层，新分层自动
  克隆规则。同一 `DROP` 在 PROD 分层拦截转审批、在 DEV 直接放行。
- **多语句整批判定**：批量粘贴 / 堆叠语句（`SELECT 1; DELETE …`）逐条判级取最严格结论，
  预检、同步执行、异步执行三条路径一致；工单聚合展示全部命中规则。
- 按引擎方言判定（MySQL / PostgreSQL / Oracle / MongoDB 语法差异），注释剥离防绕过。
- 判定结论以**机器可读的规则引用**（`code` + 参数）回传，界面按当前语言渲染；服务端同时给出
  中文原文作为兜底，两边不会各说各的。

### 执行窗口（「班车」，ADR 0015）

维护车次里一晚上几十条 DDL 逐条等人批不现实，而「提前把规则改松、事后忘了改回去」比没有
审批更糟 —— 没人知道门还开着。执行窗口把那个口头约定变成系统里可查、可审计、**到点自动
关上**的东西。

- **只把 `approve` 降为 `allow`**。能力矩阵判 `deny` 的仍然 `deny`：只读角色不会因为到了
  凌晨两点就能写生产库。风险等级也不降 —— 窗口改变的是流程，不是事实。
- **按库开**，库名必填：一台实例底下往往混着不同业务的库，放开面越小越好。
- 放宽发生在**判定函数内部**，不是各个执行入口 —— 否则新加一条路就要记得也放宽，
  而那类遗漏的表现是「同一条语句在终端免审批、在后台执行却要审批」。
- 所有失败方向都朝严：读不到窗口表 / 时区解析不出来 / 库名为空 / 定义写不通 → 不生效或当场拒绝。
- 窗口放行的每条命令，审计 `operator` 字段指回是**哪个窗口**放的。

### 总览

登录落地页（不再直接进终端）。从前进来直接就是连着生产库、光标在等你敲字的提示符 ——
把唯一能改动真实数据的地方当默认页，等于每次开工都先站到闸门里面。

这一页汇总：待我审批的工单、等我执行的通过单与停在人工闸上的升级单、当前开着的执行窗口、
实例概况、近期审计与网关状态。**不新增任何接口，也不新增任何权限面** —— 每块数据都是用户
本来就能自己去拉的那一个接口，卡片按 `auth.menus` 收敛，各卡片并发加载且各自失败各自算
（一块取不到不该让整页空掉）。

### Web 终端（xterm.js 真终端）

- WebSocket 流式执行（不可用自动回退 REST），psql/mysql 风格元命令（`\dt` `\d` `\l` `\x`
  `\G` `\conns` `\c <db>` 等）。
- 实例树按 环境 → 类型 → 实例 组织；**搜索覆盖实例、库与表**。库表不随连接列表下发 ——
  每台实例要单独连过去 introspect 一次，所以探查过的立刻可搜，其余的由人点「全部探查」
  显式发起（并发受限、进度可见），界面上写清还有几台没搜。PostgreSQL 的表按库单列一笔
  （它的 `information_schema` 是按库的）。
- Oracle 的对象树第二层是 **OWNER（schema）**，不是服务名；终端里切 schema 之后触发的
  工单、审计、后台任务记的都是那个 schema，批准后执行会切回同一个地方。
- 结果网格 / 垂直显示 / 列宽截断提示，SQL 实测耗时，会话日志（含审计标注）一键导出。
  终端与结果表之间可上下拖分；左右两栏可折叠，宽度可拖（执行上下文默认收起），
  拖动不会把终端挤到断行 —— 中间那栏有下限。
- 快捷脚本：常用 SQL 存为片段，`Alt+1…9` 一键键入 —— 与手工输入走同一判定通道。
- 命中审批规则时弹出提交卡（必填原因），生成审批单 `AP-xxxx` 与审计 ID。

### 审批

- 多步审批链 + 超时策略（自动拒绝 / 自动升级 / 继续等待，后台定时扫描），自审开关，
  列表分页 + 服务端搜索（单号 / 实例 / 库 / 命令 / 发起人）。
- **通过不执行任何命令** —— 通过后通知发起人，由他回到本页点「执行」，一张单只能执行一次
  （`WHERE executed_at IS NULL` 兜底）；执行前会再判一次规则。升级单的工单不走这条路，
  它的执行归发布流水线（ADR 0010）。
- 待办行右侧独立一列放操作（审批 / 拒绝 / 执行），详情单独入口。**最终状态以数据库上
  那次执行的结果为准**：目标库拒绝了这条语句，单子就显示失败，而不是「已执行」；
  详情里能看到那次执行的输出与影响行数（迁移 0032 起单独存 `exec_status`，不与审批状态合并）。
- **外部飞书审批（审批魔方）**：高危命令推送飞书交互卡片，回调驱动执行；回调带签名校验 +
  IP 白名单，外发内容全量脱敏。见 `docs/external-approval-setup.md` 与 ADR 0003。

### SQL 脚本

- 上传 `.sql` 管理 / 在线查看，逐语句扫描判级（按可配置的扫描基准分层，ADR 0014）；
  检出高危则整脚本转审批 —— 审批单引用已上传文件（校验哈希），发起人执行时重新读文件、
  校验哈希、逐语句重判再逐条执行；全安全脚本直接逐条执行并逐条审计。
- **同一个脚本不会被点两次跑两遍**：下发期间整个扫描弹窗被遮罩盖住，连关闭都不行 ——
  按钮变灰只挡得住「再点一次执行」，挡不住「关掉重新扫一遍」。下发有界超时，遮罩必然散去。

### 异步执行 · 数据导出

- **异步执行**：30–60min+ 的长语句/存储过程后台跑，流式收集 `RAISE NOTICE` 进度日志，
  执行前过同一判定链；超时可配（默认 90min）。
- **异步导出**：仅允许单条只读查询（写操作/写文件子句一律拒绝），结果流式写出为 ~100MB
  分卷、AES-256 加密 zip（带 UTF-8 BOM，Excel 中文不乱码），按任务发放解压口令；
  行数 / 字节 / 执行超时上限均为运行时设置（系统设置 · 网关），失败任务不遗留孤儿文件。

### 敏感字段脱敏（ADR 0009）

脱敏落在**结果离开网关之前**，不是前端打码 —— 后者等于把明文完整发到浏览器再请它不要显示，
而那份数据在被"隐藏"之前已经躺在浏览器缓存、沿途反代日志和前端错误上报里了。
整个网关只有两处把行读出来（终端结果与导出），两处都过同一层。端到端测试直接断言
**原始响应体里明文一个字节都不能出现**。

### 变更发布流水线（CI/CD）

- **流程可自定义**：一条流程 = 有序阶段列表，阶段类型有 `规范审查 / 人工审批 / 备份回滚点 /
  执行变更 / 执行后校验 / 人工确认 / 结果通知`；可按分层限定流程（如"开发自助发布"只对 DEV 生效），
  可设默认流程。内置两条模板，管理员在「流程」页拖动增删改。
- **发布单以 pipeline 形式展示状态**：每个阶段独立记录 `待开始 / 执行中 / 等待处理 / 已完成 /
  失败 / 已跳过`、耗时、日志与审查结果；点阶段看详情，人工确认阶段可在页面上放行。
- **发布不是执行旁路**：执行阶段**下发前再判一次**闸门 —— 发布单可能在审批里停了几小时，
  期间字典、实例归属、发起人角色都可能变；判定按语句下发那一刻的规则算，且逐条写审计（挂发布单号）。
- 审批阶段复用既有审批单与审批链（飞书 / 审批魔方 / 控制台四个入口都算数）；审批**通过本身不执行**，
  执行仍由执行阶段完成 —— 否则同一变更会被应用两次。网关重启时：`running` 判失败（执行结果未知，
  不重跑）、`waiting` 原样保留、`pending` 重新入队。

### 项目

数据库与升级单的归属，自己的一页。它从「配置」页搬出来，因为读者不是同一批人：配置实例的是
DBA，按项目跟进升级单的是业务线上的人。页面只做归属与跟进（项目增删改、名下有多少库多少张单，
点进去落到按项目筛过的升级单列表）；把库归到哪个项目仍在「配置」页做 —— 那件事要对着实例
底下的库来点。

### 开放接口（外部系统提单）

- **一个外部系统一把凭据**（`Authorization: Bearer <key>.<secret>`），在【设置 · 开放接口】签发，
  绑定一个**服务账号** —— 该账号的角色决定这个系统能发布到哪些实例、什么变更要走审批，审计行记
  `actor=服务账号 / operator=API:<凭据名>`。可按凭据配 IP 白名单、权限范围（建单 / 查询 / 预检）、随时停用或吊销。
  明文密钥只在签发时回显一次（库里只有 bcrypt 哈希）。
- **提单**：`POST /api/v1/open/releases`，JSON 传 `sql`、`script`（或 `scriptBase64`），
  或 `multipart` 直传文件 `-F file=@upgrade.sql`；实例与流程都可以用**名字**寻址。脚本落盘并记录摘要，
  执行阶段重新读文件并校验哈希——审查过的字节和执行的字节是同一份。
- **幂等**：带上你自己的单号 `externalRef`，重试返回同一张升级单（数据库唯一索引兜底，并发重试也不会下发两次）。
- **查询与预检**：`GET /api/v1/open/releases/{relNo}` 拿各阶段状态与日志；
  `POST /api/v1/open/sql-review` 只做规范审查不建单，用作 CI 合并前门禁；
  `GET /api/v1/open/instances`、`/open/pipelines` 供集成方查可用实例与流程名。
- 走的是**同一条流水线**：同样的流程模板、规则库、审批链、执行前复判与审计链。开放接口只是一扇门，
  不是第二条执行通道。

### 数据库规范审查（MySQL / TiDB / DWS / Oracle）

- **87 条内置规则**，按公司四份规范（`docs/` 下 MySQL / TiDB / Oracle / DWS）重写，每条标注
  **规范分级与出处**（高危 / 强制 / 建议；规范未覆盖的标「平台内置」）——被拦下来的人能回去读原文。
  覆盖 DML、DDL、表结构、命名、索引、安全、性能七类，按**方言**作用域生效：
  TiDB 禁外键、DWS 建表必须 `DISTRIBUTE BY`、Oracle 用 `VARCHAR2` 而非 `VARCHAR`、
  MySQL 强制 InnoDB + utf8mb4，通用规则如"建表必须有主键""新增 NOT NULL 列必须给 DEFAULT"
  "UPDATE/DELETE 必须带 WHERE"。
- 规则的**级别（拦截 / 警告 / 提示）、开关、参数、文案**都在库里，控制台即改即生效；升级只补新增
  规则，不覆盖运维已经调过的策略。可自建正则规则（编码自动加 `custom.` 前缀）。
- 判的是"**写得对不对**"，与高危命令字典判的"**危不危险**"分开；结论只被发布流水线的审查阶段消费
  （`error` 级命中是否卡发布由流程配置决定），终端执行链路不受影响。上线前可在「审查」页自查。

### 审计

- 每条审计 `hash = SHA256(prev_hash + payload)` 构成防篡改哈希链（唯一约束防分叉），
  记录环境 + 分层**双快照**；命令中的口令语法全引擎脱敏。
- 按风险 / 时间范围（24h / 7 天 / 30 天）服务端过滤，分页，CSV 导出；涉及表列表化展示，完整命令入详情。

### 权限与账号

- 角色 × 菜单开关 × 能力矩阵三态（放行 / 审批 / 拒绝）在线编辑；高危命令字典逐分层指定生效等级。
- 能力维度：`SELECT / INSERT·UPDATE / DDL / GRANT / 管理连接 / 审批 / EXPLAIN / 发起发布单`。
  最后一个（`release`）管的是**能不能发起发布**，与语句本身能不能跑是两个问题：可以做到"开发自助发布、
  预发布必须走审批、生产一律不许外部发起"，而不必把 `DDL` 在生产整个关掉（那会连带堵死终端和审批通道）。
  三态在这里读作：放行 / 必须走含审批阶段的流程 / 不允许发起。升级时按各角色**同分层的 `write` 等级**回填，
  行为与升级前一致，且每个格子都有实际存在的行（不是"查无此行=放行"的默认值）。
- 菜单开关含「变更发布」（`pipeline`，发布单页与流程页共用）；规范审查页挂在「Web 命令行」下 ——
  上线前自查是写变更的一部分，不该是另一项特权。
- 管理员建号（设初始密码即激活）、邀请用户、成员增删与搜索；实例按标签限定可访问角色。

### 会话与安全

- 会话 TTL、空闲自动锁定、TOTP MFA（自助绑定 / 强制开关 / 生产操作步进验证按连接记忆宽限期）、
  登录 IP 白名单（默认关，放行 loopback）；JWT 密钥与连接口令加密密钥解耦，支持 JWT 轮换。
- 连接口令 AES-GCM 静态加密；实例维护态限制下发并审计。

### 系统设置（运行时生效，免重启）

网关策略 / 执行与异步超时 / 导出上限与超时 / 审批链与超时策略 / 会话与 MFA / IP 白名单 /
Webhook（HMAC-SHA256 签名 + 指数退避重试）/ 飞书通知 / 外部审批对接 / 开放接口凭据，均落库持久化。

## 生产部署

```bash
# 1. 打包前的闸：生产环境不得含模拟数据
(cd backend && go test ./internal/bootstrap/ -run 'TestProductionServesNoSimulatedData|TestSimulationDefaultsToOff|TestSimulatedPathsAreDocumented' -count=1 -timeout 10m)
# 2. 前端
(cd frontend && npm ci && npm run build)                 # 产物 frontend/dist/，部署时放到后端的 web_dir
# 3. 后端（交叉编译 linux/amd64，纯 Go 无需 C 工具链）
(cd backend && GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w -X main.version=$(git describe --tags --always --dirty)" -o ../dist/vela-gateway ./cmd/server)
```

单二进制同时提供 API 与前端 SPA，内嵌 SQL 迁移；子命令 `version` / `migrate` / `init`。
服务端**只产出 Linux 二进制** —— 在 Windows 工作站上构建时也一样，那台机器不是部署目标。

完整步骤（MySQL 准备、迁移、初始化管理员、systemd 托管、TLS、环境变量一览、升级注意事项）
见 **`DEPLOY.md`**。

**升级已有环境的顺序**：备份数据库 → 停旧进程 → `./vela-gateway migrate` → 起新进程 →
`./vela-gateway version` 确认版本。反过来做，新二进制会对着旧表结构跑；迁移之后也不要单独
回滚二进制（旧代码按旧列名查询，列已经不在了）。这类失败朝"关"的方向 —— 规则查不到就拒绝 ——
不会变成放行，但会是一场故障。

### 启动自检：审批人

每次启动会检查"这些审批环节到底还有没有人能批"，命中就打 WARN 日志（不阻止启动）：

| 情形 | 后果 |
|---|---|
| 角色没有成员，或成员**全是服务账号** | 工单根本建不出来（服务账号登录不了控制台，无法审批） |
| 链上**恰好一个人**且未开自审批 | 工单建得出来，但由他本人发起的**永远没人能批** |
| 启动那一刻已经卡住的存量待办 | 现在就已经没人能处理 |

第二条是最容易漏的：角色有成员、审批链建得出来、工单也创建成功，每一层校验都"通过"，
然后两人控制让它们一张都批不掉——单子静静堆在待办里，不报错也不推进。**上线后请看一眼
这几行日志**：

```
WARN 审批人自检: 默认审批链(DBA 负责人) severity=deadlock
     problem=链上只有 Lin Wei 一个人能批。两人控制下，由他本人发起的工单将没有任何人可以审批
     fix=为该角色再加入一名真人成员；若确为单人运维，可在「设置」中打开「允许自审批」
```

两条出路：给该角色**再加一名真人**（推荐，两人控制才成立），或在「设置」中打开
**允许自审批**（单人运维的逃生门；它只解除"自己不能审自己"，**不会**把人放上审批链）。

自检只看启动那一刻的快照，之后堆积的卡单它不会知道——它是上线检查项，不是监控。

## API

三套鉴权面，别混用：

| 面 | 前缀 | 鉴权 | 谁在调 |
|---|---|---|---|
| 控制台 | `/api/v1` | `Authorization: Bearer <JWT>` | 登录的人 |
| 开放接口 | `/api/v1/open` | `Authorization: Bearer <key>.<secret>` | 外部系统 |
| 回调 | `/api/v1/approvals/lark/callback` | 共享密钥 | 审批服务 |

一律 HTTP 200，业务结果在包体里：`{ code, msg, data }`（`0` 成功、`42200` 命令被拦截转审批、
`42800` 需二次验证、`40300` 无权……完整码表见契约文件开头）。

- **在线接口文档**：`GET /docs`（本地 http://localhost:8080/docs ）—— Swagger UI，带 **Authorize** 与
  **Try it out**，`#/tag/operation` 深链可直接分享。资源是 **vendored 进二进制**的（`internal/handler/swaggerui`，
  gzip 后约 415KB，Apache-2.0，LICENSE 随文件放），**不走 CDN**：断网机器上照常打开，这也是网关最常见的部署环境。
  Try it out 打的是真接口，对生产实例执行前想清楚。
- **完整契约**：`backend/docs/openapi.yaml`（运行时 `GET /openapi.yaml`）。**全部 130 条路由都在里面**
  （101 条路径）—— 由 `TestOpenAPICoversEveryRoute` 静态守着：新增路由没写进文档，测试直接失败；
  文档里写了不存在的路由，也会被 `TestOpenAPIDocumentsNoGhostRoutes` 挑出来。每个操作的 `summary`
  带守卫标注，形如 `[perms · admin]`、`[scope release:create]`，回答"我能不能调"。
- **外部系统对接**：`docs/开放接口对接文档.md` —— 怎么拿凭据、幂等怎么算、状态怎么轮询、
  各个错误码代表什么、最小接入清单。契约说不清的都在那里。

## 测试与质量

- **后端**：`go test ./... -timeout 20m` —— 以 **httptest 黑盒回归网**为主
  （`backend/internal/bootstrap/` 下 136 个测试文件，启动完整应用实跑 HTTP 接口，覆盖判定链、
  多语句、审批链、审计链、脱敏、导出上限、执行窗口、会话安全等），另有引擎方言 / 口令脱敏 /
  规范审查等单元测试。
  bootstrap 包每个用例都会启动一次完整应用并灌种子数据，整包约 12 分钟，**超过 `go test`
  默认的 10 分钟包超时**，所以上面那条命令带了 `-timeout`；不带会在跑完前被判超时失败。
- **前端构建**：`npm run build` = `vue-tsc` 类型检查 + Vite 打包 + vue-i18n 严格模式构建期预编译
  （非法文案直接构建失败）。
- **前端单元测试**：`npm run test:unit`（179 个用例，Playwright runner 跑 `src/lib/*` 的纯逻辑：
  终端行编辑器、结果渲染的控制字符、会话日志脱敏、导入表解析、规则文案等）。
  它用 `tsconfig.unit.json` 把 `@/locales` 指向一个测试替身 —— 裸 Node runner 既读不了 `.json5`
  也没有 `localStorage`，而那次失败炸的是**收集阶段**：整套一个用例都不执行。替身只替掉加载，
  词条与 vue-i18n 都是真的，因为这里的断言看的正是用户会读到的那段中文。
