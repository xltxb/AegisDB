# AegisDB 数据库管理网关

面向 DBA 与运维团队的统一数据库访问网关：所有数据库操作经 Web 终端 / 脚本 / 异步任务 /
数据导出 / 发布流水线 / 开放接口下发，由网关**逐语句实时判定** —— 放行、拦截或转审批；
审批通过后由**有权者自己**执行（见 ADR 0010）。全程写入防篡改审计哈希链，可经 Webhook /
飞书外推。支持真实连接 MySQL 家族（MySQL / PolarDB / TiDB / MariaDB）、PostgreSQL 家族
（PostgreSQL / GaussDB(DWS)）与 Oracle。

```
db-gateway/
├─ backend/     Go + Gin + GORM 后端（REST + WebSocket；风险引擎/RBAC/审批/审计哈希链/多引擎真实执行）
├─ frontend/    React 19 + TS + Vite 前端（Vela 设计系统，明暗双主题，中英双语，xterm.js 真终端）
├─ frontend-vue/ 被它取代的 Vue 3 实现，留作对照与回退（见文末「两套前端」）
├─ docs/        PRD / 前后端开发文档 / 交互原型 / ADR / 四份数据库规范 / 外部审批与开放接口对接指南
├─ deploy/      systemd unit + 环境变量模板
└─ docker-compose.yml  本地 MySQL 8 + Redis 7（可选；后端目前不使用 Redis）
```

## 快速开始

### 一键启动（Windows，最省事）

分别双击 **`backend\run-sqlite.bat`**（后端，SQLite，零依赖）与 **`frontend\run-dev.bat`**（前端，Vite），
然后浏览器打开 http://localhost:5173 ，用 `linwei@vela.io` / `vela123` 登录。

### 手动启动

```bash
# 后端（默认 APP_ENV=dev → SQLite，写 ./vela-gateway.db，自动迁移 + 演示数据）
cd backend && go run ./cmd/server            # 监听 :8080，健康检查 GET /healthz

# 前端
cd frontend && npm install && npm run dev    # http://localhost:5173（代理 /api 到 :8080）
```

生产路径（MySQL 8）：`APP_ENV=prod go run ./cmd/server`，DSN 见 `backend/configs/config.yaml`
或环境变量 `VELA_MYSQL_DSN`。环境变量一览与生产部署完整步骤见 **`DEPLOY.md`**。

### 演示账号（本地 seed）

空库首次启动只建**一个**平台管理员：`linwei@vela.io` / `vela123`（全菜单）。seed 不创建任何实例，
登录后到「配置」页新增实例；未填凭据的实例在 dev 环境走仿真执行（见文末说明）。
dev 构建的登录页会预填这组账号，生产构建不预填也不提示。

要验证**菜单权限收敛**，在「权限」页自建角色与用户即可；一个用户可挂多个角色，权限取**所有角色的并集**。

### 风险判定 · 环境/分层模型

- 判定链：`菜单权限 → 能力矩阵(角色×能力×分层) → 高危命令字典(命令×分层) → 无 WHERE 拦截(分层)`。
  四层规则**都按分层存**：最后一层拦截不带 WHERE 的 DELETE/UPDATE，2026-09 前它是一个全局开关，
  于是无法只对 dev 关掉（迁移 0030 起改为按分层，开关在【分层】页）。EXPLAIN 独立成档：`EXPLAIN` 只看计划、按只读判；
  而**会真的执行**被包住语句的那些形式按真实执行判 —— `EXPLAIN ANALYZE`／英式拼写
  `ANALYSE`、选项表里的 `(ANALYZE …)`、以及 DWS/GaussDB 的 `EXPLAIN PERFORMANCE`。
- **会话级设置短路**：`SET search_path …`、Oracle `ALTER SESSION SET …` 这类只影响本连接的语句，
  只查 `select` 能力（deny 仍 deny），跳过字典与无 WHERE 检查 —— 否则运维为拦 `ALTER TABLE` 写下的
  "ALTER" 会连切 schema 一起拦掉。`SET GLOBAL / PERSIST / PASSWORD / ROLE / SESSION AUTHORIZATION`、
  `@@GLOBAL.`、`ALTER SYSTEM` 不放宽，按原动词判。
- **分层标签（tier）承载规则，环境（environment）归属实例**：内置五个分层 —— `prod` 生产、
  `gli` 法务、`staging` 预发布、`uat` 演练、`dev` 开发；可自建环境并挂到任一分层，新分层必须从
  现有分层克隆规则（能力矩阵 + 高危字典）。同一 `DROP` 在 PROD 分层拦截转审批、在 DEV 直接放行。
  每个分层还带一组属性位：强制 MFA、终端红色警告、计入待审批、脚本扫描基准、无 WHERE 拦截
  （内置五分层里只有 prod 开前四项，dev 关无 WHERE 拦截）。不能删除仍有环境挂靠、作为扫描基准
  或最后一个分层；删环境必须指定实例迁往哪个环境。
- **多语句整批判定**：批量粘贴 / 堆叠语句（`SELECT 1; DELETE …`）逐条判级取最严格结论，
  预检、同步执行、异步执行三条路径一致；工单聚合展示全部命中规则。
- 按引擎方言判定（MySQL / PostgreSQL / Oracle 语法差异），注释剥离防绕过。
- 判定结论以**机器可读的规则引用**（`code` + 参数）回传，界面按当前语言渲染；服务端同时给出
  中文原文作为兜底，两边不会各说各的。
- 实例上的「策略」字段（`strict / approve-1 / audit-only`）与设置里的「默认网关策略」目前只做
  存储与校验，**判定层不读它**；界面上它只影响实例树的「高危 / 受限」标签。

### 执行窗口（「班车」，ADR 0015）

维护车次里一晚上几十条 DDL 逐条等人批不现实，而「提前把规则改松、事后忘了改回去」比没有
审批更糟 —— 没人知道门还开着。执行窗口把那个口头约定变成系统里可查、可审计、**到点自动
关上**的东西。

- **窗口本身要走审批**：任何人可在「班车」页申请，提交后生成 `AP-` 审批单，走默认审批链、超时策略
  与自审开关，**通过后才生效**，待审批的窗口不放行任何语句。编辑窗口会让它重回待审批；
  修改/撤回限申请人或管理员；删除不走审批、立即关门。每次变动写审计。
- **只把 `approve` 降为 `allow`**。能力矩阵判 `deny` 的仍然 `deny`：只读角色不会因为到了
  凌晨两点就能写生产库。风险等级也不降 —— 窗口改变的是流程，不是事实。
- **按库开**，库名必填（从实例真实库列表选，探查失败时退回手输）。时间模型两种：
  「周期班车」按 IANA 时区（默认 `Asia/Shanghai`）给出每班开始/结束（默认 02:00–04:00，
  结束≤开始表示跨午夜，按发车日算星期）、发车日（ISO 1–7，空=每天）、可选停运时间；
  「一次性」用绝对起止时刻（存 UTC）。
- 放宽发生在**判定函数内部**，不是各个执行入口 —— 否则新加一条路就要记得也放宽，
  而那类遗漏的表现是「同一条语句在终端免审批、在后台执行却要审批」。
- 所有失败方向都朝严：读不到窗口表 / 时区解析不出来 / 库名为空 / 定义写不通 → 不生效或当场拒绝。
- 窗口放行的每条命令，审计 `operator` 字段指回是**哪个窗口**放的。列表区分
  待审批 / 已驳回 / 已撤回 / 已停用 / 进行中 / 已到期 / 未到点。

### Web 终端（xterm.js 真终端）

- WebSocket 流式执行（不可用自动回退 REST；REST 路径不可取消），心跳 20s、断线退避 1→15s 重连，
  执行中断线会提示「结果未知」；会话被撤销（登出 / 停用 / 改密）时直接跳登录页。
- 行编辑器：↑/↓ 历史（到底部恢复草稿）、Home/End、Ctrl+A/E 行首行尾、Ctrl+U 清行、Ctrl+L 清屏、
  Ctrl+C 空闲时丢弃续行、执行中经 WebSocket 发取消帧（等目标库回执）；有选区时 Ctrl/Cmd+C 是复制。
  语句以 `;` 结束或以 `\g`/`\G` 结尾才提交，否则进入续行。输入行实时语法高亮。
  粘贴 ≥2 条语句时自动改开「粘贴 SQL」弹窗整批提交（Ctrl+Enter 执行）。
- psql/mysql 风格元命令，按引擎翻译成目录查询后**照常判定与审计**（判定看到的是原文，
  字典规则不会被翻译绕过）：

  | 命令 | 作用 |
  |---|---|
  | `\l` `\list` `\dn` | 列数据库 / schema（Oracle 用户即 schema） |
  | `\dt` `\dv` `\di [表]` `\ds` `\df` | 列表 / 视图 / 索引（MySQL 必须带表名）/ 序列 / 函数（仅 PG） |
  | `\du` `\dg` `\dp` `\z` | 列用户角色 / 表权限（仅 PG） |
  | `\d` `\d 表` `\d+` | 列所有表 / 描述表（PG 带类型长度、Collation、默认值，并自动附「索引:」段） |
  | `DESC 对象` | Oracle 连同义词一起解、带长度精度；PG 家族与 SQLite 翻成目录查询；MySQL 原样执行 |
  | `\conninfo` | 当前库 / 用户 / 版本 |
  | 语句末 `\G` | 本条竖排；`\x [on/off/auto]` 持久切换 |
  | `\c 库` `\connect` `\u` `USE 库` | 切换当前目标库（客户端状态，同步到标签页与树） |
  | `\conns` `\clear` `\?` `\h` | 列网关内连接 / 清屏 / 帮助（按引擎只列支持的命令） |

  服务端另有一层客户端语法翻译（判定之后、下发之前）：Oracle 的 `SHOW USER / CON_NAME / RELEASE /
  PARAMETER x`、`DESC[RIBE]`、`EXEC proc(...)`（按写判）；PG 的 `\l \dn \du \d \dt \dv \di \ds`；
  MySQL 剥掉尾部 `\G/\g`。`\q \timing \e` 均未实现。
- 实例树按 环境 → 类型 → 实例 组织，可切「按数据库类型」分组；**搜索覆盖实例、库与表**
  （最多列 80 条库/表命中）。库表不随连接列表下发 —— 每台实例要单独连过去 introspect 一次，
  所以探查过的立刻可搜，其余的由人点「全部探查」显式发起（并发 4、进度可见），界面上写清
  还有几台没搜。PostgreSQL 的表按库单列一笔（它的 `information_schema` 是按库的）。
  另有服务端**元数据缓存**：`GET /metadata/search` 只搜标签授权内实例的表清单与列结构，
  由「配置」页的「立即同步」或定时同步（设置 › 元数据同步）填充；缓存是只读副本，
  判定 / 执行 / 导出仍走实时库。
- Oracle 的对象树第二层是 **OWNER（schema）**，不是服务名；终端里切 schema 之后触发的
  工单、审计、后台任务记的都是那个 schema，批准后执行会切回同一个地方。owner 下出现
  「无效对象 N」时可一键「全部重编译」（整批判定、逐个审计，结果弹窗列已修复 / 仍失败）。
- 点表看建表 DDL（Oracle `DBMS_METADATA`、PG 系按 `information_schema` 重建、MySQL `SHOW CREATE`），
  点函数 / 存储过程 / 包 / 触发器看源码；语法高亮、一键复制；Oracle 可编程对象可单独「编译」
  （走 DDL 三层闸门）。
- 结果：终端表格按宽度 water-fill、列宽截断时提示加 `\G` 竖排、控制字符剔除；
  「表格视图」开关切到 HTML 网格（序号列、sticky 表头、`∅` 表 NULL、数值右对齐、复制为 TSV）。
  每条语句最多回传 200 行（带 `truncated` 标记），SQL 实测耗时。
- 布局：终端与结果表之间可上下拖分（默认 42%，15–80%，键盘可调、双击复原）；左右两栏可折叠、
  宽度可拖（树 180–560px、上下文 240–620px，执行上下文默认收起），中间那栏有 420px 下限，
  拖动不会把终端挤到断行；「沉浸模式」同时收起两侧。
- 打开或切到带红色警告的分层时先弹「环境 / 实例 / 库」确认（每个标签页只问一次）；
  页顶红「生产环境操作中」/ 黄「受管控环境操作中」横幅带「结束会话」。
- 快捷脚本：常用 SQL 存在服务端（每人 50 条、正文 8 KB、名称 64 字），`Alt+1…9` 一键键入 ——
  与手工输入走同一判定通道；在带红色警告的分层需 **4 秒内按两次**确认。
- 会话日志一键导出：`vela-<环境-实例>-<时间>.log`，UTF-8 BOM，含实例 / 库 / 操作人 / 时间头，
  剥 ANSI，口令按后端同一套规则打码，最多 5000 条超出丢最旧；导出本身写一条审计。
- 命中审批规则时弹出提交卡（必填原因），生成审批单 `AP-xxxx` 与审计 ID；命中步进验证时弹 6 位码框。
- 「上传脚本」「已上传脚本」「示例」从终端动作栏进入扫描弹窗（见「SQL 脚本」）。

### 审批

- 审批链 = `owner` 角色的全部真人成员（无则 `admin`），服务账号一律排除；发布流程的审批阶段可用
  `approverRole` 指定别的角色。**任一链成员一次决定即终结整单**（approve-1），不逐级推进。
- 超时策略（后台每 60s 扫描，阈值默认 720 分钟）：`auto-reject` 置为已过期、审计、通知发起人并回写
  审批魔方；`auto-escalate` 只把单标为「已升级」并写一条告警审计，**审批人不变、单仍待审**；
  `keep-waiting` 继续等待。自审开关；列表分页 + 服务端搜索（单号 / 库表 / 发起人）+ 六态筛选 +
  「待我审批 / 全部」范围，`?ap=AP-xxx` 可深链。驳回不强制填理由；发起人可**撤回**未执行的单。
- **通过不执行任何命令** —— 通过后站内通知发起人，任何对该实例有标签授权、自身能力矩阵放行、
  过了 MFA 的人都可回到本页点「执行」；一张单只能执行一次（`WHERE executed_at IS NULL` 兜底）；
  执行前会再判一次规则。执行窗口单、含敏感字段的导出单、升级单不走这条路（分别由窗口生效、
  导出 worker、发布流水线接手，详情里有说明；ADR 0010）。
- 待办行右侧独立一列放操作（审批 / 拒绝 / 执行 / 撤回），详情单独入口。**最终状态以数据库上
  那次执行的结果为准**：目标库拒绝了这条语句，单子就显示失败，而不是「已执行」；
  详情里能看到判定分层、审批链、那次执行的输出与影响行数（迁移 0032 起单独存 `exec_status`）。
- **外部飞书审批（审批魔方）**：高危命令推送飞书交互卡片，回调把单置为通过/驳回（不执行）；
  回调带签名校验 + IP 白名单，外发内容全量脱敏；总开关关闭时回调端点也拒绝。
  见 `docs/external-approval-setup.md` 与 ADR 0003。与之并列的还有**飞书群通知**：每张新审批单
  向自定义机器人推一张卡片（设置 › 通知），两者是独立的两套配置。

### SQL 脚本

- 「上传」页：拖拽或选择 `.sql` / 文本文件，列表显示来源（终端 / 上传）、大小、归档路径，可下载、删除；
  单文件 ≤ 15 MB（按实际读取计，不信客户端声明），保存目录由设置 `script.savePath` 决定（默认 `uploads/`）。
- 扫描与执行在终端动作栏：逐语句扫描判级（按可配置的扫描基准分层，ADR 0014）；
  检出高危则整脚本转审批 —— 审批单引用已上传文件（校验哈希），发起人执行时重新读文件、
  校验哈希、逐语句重判再逐条执行；全安全脚本直接逐条执行并逐条审计。扫描弹窗必选目标库。
- **同一个脚本不会被点两次跑两遍**：下发期间整个扫描弹窗被遮罩盖住，连关闭都不行 ——
  按钮变灰只挡得住「再点一次执行」，挡不住「关掉重新扫一遍」。下发有界超时（120s），遮罩必然散去。

### 异步执行 · 数据导出

- **异步执行**：30–60min+ 的长语句/存储过程后台跑，流式收集 `RAISE NOTICE` 进度日志，
  执行前过同一判定链；超时由运行时设置 `gateway.asyncExecTimeout` 决定（默认 90min，
  目前只能经 `PUT /settings` 改，设置页没有控件）；页面无取消。监管角色（admin / owner / audit）
  看全部任务，其余只看自己的。
- **异步导出**：仅允许单条只读查询（写操作/写文件子句一律拒绝），结果流式写出为 ~100MB
  分卷、AES-256 加密 zip（带 UTF-8 BOM，Excel 中文不乱码），按任务发放解压口令；
  行数 / 字节 / 执行超时上限均为运行时设置（默认 500 万行 / 2 GB / 1800s，0 = 不限），
  失败任务不遗留孤儿文件。勾选「包含敏感字段（原值）」的导出停在待审批，生成高危审批单，
  批准后由导出 worker 后台执行。
- 归档保留 `export.retentionDays` 天（默认 3，0 = 永久）：每小时清一次、启动先跑一次，只删文件、
  任务记录保留。提交的 SQL 正文 ≤ 15 MB。
- 网关重启时把上次进程遗留的 `running` 导出 / 异步任务标失败（不重跑）。worker：导出 3、异步 3、
  发布 3，队列各 256，满则任务立即失败。

### 敏感字段脱敏（ADR 0009）

脱敏落在**结果离开网关之前**，不是前端打码 —— 后者等于把明文完整发到浏览器再请它不要显示，
而那份数据在被"隐藏"之前已经躺在浏览器缓存、沿途反代日志和前端错误上报里了。
整个网关只有两处把行读出来（终端结果与导出），两处都过同一层。端到端测试直接断言
**原始响应体里明文一个字节都不能出现**。

规则在设置 › 敏感字段维护：`表名 + 字段名`（表名留空 = 所有表），方式 `partial` 留头留尾 /
`full` 全部 / `hash` 同值同码；只匹配选择列表（含别名与表达式引用），`WHERE` 里引用不打码。
规则缓存 5 秒，增删改立即失效；库读失败时沿用上一份规则而不是回空。

### 变更发布流水线（CI/CD）

- **流程可自定义**：一条流程 = 有序阶段列表，阶段类型有 `规范审查 / 人工审批 / 备份回滚点 /
  执行变更 / 执行后校验 / 人工确认 / 结果通知`；可按分层限定流程（如"开发自助发布"只对 DEV 生效），
  可设默认流程。内置两条模板：「标准发布流程」（默认、全分层）与「开发自助发布」（仅 dev：审查→执行）。
  管理员在「流程」页用上/下箭头排阶段；审查阶段可选拦截级别 `error / warn / 只记录`，
  审批与人工确认阶段可指定角色并预览审批人名单，备份 / 校验阶段填 SQL（备份只允许
  CREATE / INSERT / SELECT，校验必须只读并声明期望结果空 / 非空）。
- **发布单以 pipeline 形式展示状态**：每个阶段独立记录 `待开始 / 执行中 / 等待处理 / 已完成 /
  失败 / 已跳过`、耗时、日志与审查结果；点阶段看详情，人工确认阶段可在页面上放行。
  发布页有「我的 / 全部」（审批人或管理员）、按项目筛选、活跃单 2.5s 轮询、来源徽标（API 单带
  `externalRef`）、「终止发布」（仅待开始 / 等待处理）。新建表单：实例、库、流程、变更类型
  （自动 / DML / DDL，SELECT 计 DML、GRANT/REVOKE 计 DDL）、SQL 正文（粘贴）、原因、「预审」、MFA 码。
- **发布不是执行旁路**：执行阶段**一律先停在等待确认**（`confirmRole` 不配则创建者或可审批角色 /
  管理员点「确认执行」），确认后**再判一次**闸门 —— 发布单可能在审批里停了几小时，
  期间字典、实例归属、发起人角色都可能变；判定按语句下发那一刻的规则算，且逐条写审计（挂发布单号），
  日志回显结果集。
- 审批阶段复用既有审批单与审批链（飞书 / 审批魔方 / 控制台各入口都算数）；审批**通过本身不执行**，
  执行仍由执行阶段完成 —— 否则同一变更会被应用两次。网关重启时：`running` 判失败（执行结果未知，
  不重跑）、`waiting` 原样保留、`pending` 重新入队。发布单终止时作废其审批并回写审批魔方。

### 项目

数据库与升级单的归属，自己的一页。它从「配置」页搬出来，因为读者不是同一批人：配置实例的是
DBA，按项目跟进升级单的是业务线上的人。页面只做归属与跟进（项目增删改、名下有多少库多少张单，
点进去落到按项目筛过的升级单列表；名下有库时不能删）；把库归到哪个项目仍在「配置」页做 ——
那件事要对着实例底下的库来点。路由按 `project` 菜单键守门，但权限页的菜单网格目前没有这个开关，
项目页的可见性靠种子数据。

### 配置（数据源）

- 仅管理员可改。搜索（名称 / 地址 / 库 / 标签 / 引擎，命中高亮）、「仅看异常」、引擎筛选、环境分段、
  舒适 / 紧凑密度；按 环境 → 引擎 双层分组，每组分页 25 行。
- 每行：真连 / 仿真徽章、「库归属」（展开时实时探查库列表，每库选归属项目）、标签编辑、地址复制、
  行内改策略、点击切换 **在线 / 维护**、「立即同步元数据」、编辑。
- 新建 / 编辑：名称、引擎（7 项）、环境、`host:port`、策略、库 / Schema（Oracle 为 service name 或 SID）、
  用户名、密码（编辑留空保持；AES-GCM 静态加密）。保存后自动「测试连通性」：真的 `Ping`，
  无凭据返回不可连并说明，Oracle 缺 service name 给出可操作提示。无删除、无克隆。
- 批量：勾选后批量改策略（受管控分层二次确认）、「批量巡检」（真连、并发 4，结果仅本会话）、
  「导出所选」CSV（不含凭据）。CSV 导入：必需列 `name,engine,env,host`，可选
  `policy,database,username,password`，逐行创建并自动测连，错误按行号报告。
- **维护态**（`status=maint`）：终端 / 脚本 / 审批单执行返回「目标实例处于维护态」软空操作；
  导出、异步执行、发起发布、发布执行阶段、Oracle 编译直接拒绝；元数据同步跳过。

### 开放接口（外部系统提单）

- **一个外部系统一把凭据**（`Authorization: Bearer <key>.<secret>`，也接受 `X-Vela-Key` /
  `X-Vela-Secret` 头），在【设置 · 开放接口】签发，绑定一个**服务账号**（不能绑平台管理员）——
  该账号的角色决定这个系统能发布到哪些实例、什么变更要走审批，审计行记
  `actor=服务账号 / operator=API:<凭据名>`。可按凭据配 IP 白名单、权限范围（建单 / 查询 / 预检，
  全空 = 三项全给）、绑定一条发布流程（不绑则按目标分层默认流程）、随时停用或吊销；
  key/secret 不可轮换，只能新发 + 吊销。明文密钥只在签发时回显一次（库里只有 bcrypt 哈希）。
  服务账号不能登录控制台、不能设密码。
- **提单**：`POST /api/v1/open/releases`，JSON 传 `sql`、`script`（或 `scriptBase64`），
  或 `multipart` 直传文件 `-F file=@upgrade.sql`；实例用**名字**寻址，流程由凭据绑定或分层默认决定，
  请求里带 `pipeline` 会被整单拒绝。脚本落盘并记录摘要，执行阶段重新读文件并校验哈希 ——
  审查过的字节和执行的字节是同一份。
- **幂等**：带上你自己的单号 `externalRef`，重试返回同一张升级单（数据库唯一索引兜底，并发重试也不会下发两次）。
- **查询与预检**：`GET /api/v1/open/releases/{relNo}` 拿各阶段状态与日志；
  `POST /api/v1/open/sql-review` 只做规范审查不建单，用作 CI 合并前门禁；
  `GET /api/v1/open/instances`、`/open/pipelines` 供集成方查可用实例与流程名。
- 走的是**同一条流水线**：同样的流程模板、规则库、审批链、执行前复判与审计链。开放接口只是一扇门，
  不是第二条执行通道。

### 数据库规范审查（MySQL / TiDB / DWS / Oracle）

- **87 条内置规则**，按公司四份规范（`docs/` 下 MySQL / TiDB / Oracle / DWS）重写，每条标注
  **规范分级与出处**（高危 / 强制 / 建议；规范未覆盖的标「平台内置」）——被拦下来的人能回去读原文。
  覆盖 DML、DDL、表结构、命名、索引、安全、性能七类，按**方言**作用域生效：
  TiDB 禁外键、DWS 建表必须 `DISTRIBUTE BY`、Oracle 用 `VARCHAR2` 而非 `VARCHAR`、
  MySQL 强制 InnoDB + utf8mb4，通用规则如"建表必须有主键""新增 NOT NULL 列必须给 DEFAULT"
  "UPDATE/DELETE 必须带 WHERE"。
- 规则的**级别（拦截 / 警告 / 提示）、开关、参数、文案、分级、出处**都在库里，「审查」页按方言分 tab、
  按分级 / 分类过滤、搜索、即改即生效；升级只补新增规则，不覆盖运维已经调过的策略。
  可自建正则规则（编码自动加 `custom.` 前缀，只有自定义规则可删）。
- 判的是"**写得对不对**"，与高危命令字典判的"**危不危险**"分开；结论只被发布流水线的审查阶段消费
  （`error` 级命中是否卡发布由流程配置决定），终端执行链路不受影响。上线前可在「审查」页自查：
  选实例，或不选实例只选方言（默认 mysql），超时 120s。

### 审计

- 每条审计 `hash = SHA256(prev_hash + payload)` 构成防篡改哈希链（唯一约束防分叉），
  记录环境 + 分层**双快照**；命令中的口令语法全引擎脱敏。失败登录也写审计（actor = 输入的邮箱）。
- 按风险 / 时间范围（24h / 7 天 / 30 天 / 全部，或绝对起止时间）服务端过滤，每页 100，
  CSV 导出（`time,actor,instance,command,risk,result,approval_no,hash`）；涉及表列表化展示，
  完整命令入详情，审批单号可跳转。结果值含 `模拟(未执行)`、`已导出`、`已告警`。
  admin / owner / audit 角色看全量，其余只看自己的。

### 权限与账号

- 角色 × 菜单开关 × 能力矩阵三态（放行 / 审批 / 拒绝）在线编辑；高危命令字典逐分层指定生效等级
  （规则页点徽标循环 拦截 → 审批 → 放行，新增命令时每个分层各选一档）。
- 能力维度：`SELECT / INSERT·UPDATE / DDL / GRANT / 管理连接 / 审批 / EXPLAIN / 发起发布单`。
  最后一个（`release`）管的是**能不能发起发布**，与语句本身能不能跑是两个问题：可以做到"开发自助发布、
  预发布必须走审批、生产一律不许外部发起"，而不必把 `DDL` 在生产整个关掉（那会连带堵死终端和审批通道）。
  三态在这里读作：放行 / 必须走含审批阶段的流程 / 不允许发起。升级时按各角色**同分层的 `write` 等级**回填，
  行为与升级前一致，且每个格子都有实际存在的行（不是"查无此行=放行"的默认值）。
  权限页的矩阵目前只渲染前 7 行，`release` 行缺失，该能力暂只能经 API 编辑。
- 菜单开关 10 个：`terminal / approve / db / rules / envtier / perms / audit / settings / pipeline /
  execwindow`；规范审查页挂在「Web 命令行」下 —— 上线前自查是写变更的一部分，不该是另一项特权。
- 管理员建号（设初始密码即激活，≥ 8 位）、邀请用户（默认只读角色）、成员增删、按人限定标签范围
  （覆盖角色范围）、多角色分配（第一个为主角色）、代绑 / 解绑 OTP、重置密码（立即作废会话）。
  不能停用自己、不能停用最后一位管理员。实例按标签限定可访问角色。用户列表无搜索与分页。

### 会话与安全

- 会话 TTL（`4h / 8h / 24h`，默认 8h）；空闲自动锁定 = **注销并跳登录页**，时长 1–1440 分钟（默认 15）
  且不超过会话 TTL。登出 / 停用 / 重置密码 / 改角色会递增 token 代次，WS 每条命令前重校验。
- 登录频控按**来源 IP**：5 分钟内第 5 次失败即锁 5 分钟（返回 `42900`）；「需要 MFA」不计失败，
  MFA 码错误计失败；成功清零。服务账号永远拒绝登录，回复与密码错误一致。失败登录写审计并作为
  `login` 事件外推 Webhook。
- TOTP MFA：自助绑定 / 解绑（需当前码）、管理员代绑 / 重置；`security.requireMFA`（默认开）对带
  「强制 MFA」属性的分层做步进验证，按 `用户 + token 代次 + 实例` 记宽限（`security.mfaGraceMinutes`
  默认 30、上限 720、0 = 每条都验，登出 / 改密 / 改角色 / 重启即失效）；`security.mfaMandatory`
  （默认关）开启后未绑定 TOTP 的真人在该分层任何操作都返回 `42800`。这两项目前无界面控件，
  经 `PUT /settings` 设置。码一次一用。
- 登录 IP 白名单（默认关；IP / CIDR，逗号 / 换行分隔；loopback 永远放行；拒绝码 `40301`）作用于登录、
  WS 终端与全部 `/api/v1` 认证接口；**不**作用于 `/open`（凭据自带白名单）与审批回调（自带白名单）。
- JWT 密钥与连接口令加密密钥解耦（`VELA_JWT_SECRET` / `VELA_SECRET_KEY`），支持 JWT 轮换。
  连接口令 AES-GCM 静态加密；实例维护态限制下发并审计。

### 系统设置（运行时生效，免重启）

九个页签：网关策略 / 元数据同步 / 审批 / 会话与安全 / 敏感字段 / 通知 / Webhook / 开放接口 / 外观与语言，
均落库持久化（`tbl_setting`，`PUT /settings` 即改即生效）。

- **网关策略**：命令执行超时（1–3600s，默认 30）、上传脚本保存路径、导出保存路径、导出行数 / 字节 /
  执行超时上限、导出保留天数。
- **元数据同步**：定时同步开关（默认**关**）、间隔 1–720 小时（默认 24）、并发 1–8（默认 2）。
  调度器每小时醒一次比对间隔，**启动时不跑**，开启后要等满一个间隔才跑第一轮；跳过维护态与无凭据
  实例；单台探查上限 5 分钟、列信息上限 20 万行；单台失败只记在该实例的同步记录里。
- **审批**：超时处理（`auto-reject / auto-escalate / keep-waiting`）、允许自审、外部飞书审批（审批魔方）
  的地址 / 令牌 / 回调根地址 / 回调密钥 / 回调 IP 白名单（令牌与回调密钥加密落库、不回显）。
- **会话与安全**：会话有效期、空闲锁定与时长、强制 MFA、我的 MFA、IP 允许列表。
- **通知**：飞书群卡片（`notify.lark` 默认开、机器人地址、签名密钥、控制台回链、发送测试卡片）。
  同页的「邮件通知」「拦截即时通知」开关后端目前不读。
- **Webhook**：地址、Bearer Token（随 `Authorization: Bearer` 发送，不回显）、事件（`exec` 高危执行 /
  `login` 登录会话）、重试（最多 5 次、退避 2ⁿ s 封顶 30s、整条投递 2 分钟总时限、单次 5s、禁重定向）、
  发送测试事件、投递日志（`GET /settings/webhook/deliveries`）。载荷为事件中心格式
  （`source_system=AegisDB`、`occurred_at`、`action`、`resource`、`operator`、`summary`、`raw_payload`），
  见 `docs/事件中心平台接入文档.md`。出站目标默认拦截内网地址（SSRF 防护），生产要推内网需
  `VELA_WEBHOOK_ALLOW_PRIVATE=true`。
- **开放接口**：服务账号与凭据（见上）。**外观与语言**：中文 / English，深色 / 浅色 / 跟随系统（默认浅色）。

```bash
(cd backend && GOOS=linux GOARCH=amd64 go build -trimpath -ldflags "-s -w -X main.version=$(git describe --tags --always --dirty)" -o ../dist/vela-gateway ./cmd/server)
```

单二进制同时提供 API 与前端 SPA，内嵌 SQL 迁移；子命令 `version` / `migrate` / `init`。
服务端**只产出 Linux 二进制** —— 在 Windows 工作站上构建时也一样，那台机器不是部署目标。

完整步骤（MySQL 准备、迁移、初始化管理员、systemd 托管、TLS、反向代理信任列表、环境变量一览、
运维观测、升级注意事项）见 **`DEPLOY.md`**。

**升级已有环境的顺序**：备份数据库 → 停旧进程 → `./vela-gateway migrate` → 起新进程 →
`./vela-gateway version` 确认版本。反过来做，新二进制会对着旧表结构跑；迁移之后也不要单独
回滚二进制（旧代码按旧列名查询，列已经不在了）。这类失败朝"关"的方向 —— 规则查不到就拒绝 ——
不会变成放行，但会是一场故障。

### 启动自检：审批人

每次启动会检查"这些审批环节到底还有没有人能批"，命中就打 WARN 日志（不阻止启动）：

| 情形 | 后果 |
|---|---|
| 角色没有成员，或成员**全是服务账号** | 工单根本建不出来（服务账号登录不了控制台，无法审批） |
| 链上**恰好一个人**且未开自审批 | 工单建得出来，但由他本人发起的**永远没人能批** |
| 启动那一刻已经卡住的存量待办 | 现在就已经没人能处理 |

第二条是最容易漏的：角色有成员、审批链建得出来、工单也创建成功，每一层校验都"通过"，
然后两人控制让它们一张都批不掉——单子静静堆在待办里，不报错也不推进。**上线后请看一眼
这几行日志**：

```
WARN 审批人自检: 默认审批链(DBA 负责人) severity=deadlock
     problem=链上只有 Lin Wei 一个人能批。两人控制下，由他本人发起的工单将没有任何人可以审批
     fix=为该角色再加入一名真人成员；若确为单人运维，可在「设置」中打开「允许自审批」
```

两条出路：给该角色**再加一名真人**（推荐，两人控制才成立），或在「设置」中打开
**允许自审批**（单人运维的逃生门；它只解除"自己不能审自己"，**不会**把人放上审批链）。

自检只看启动那一刻的快照，之后堆积的卡单它不会知道——它是上线检查项，不是监控。

## API

三套鉴权面，别混用：

| 面 | 前缀 | 鉴权 | 谁在调 |
|---|---|---|---|
| 控制台 | `/api/v1` | `Authorization: Bearer <JWT>` | 登录的人 |
| 开放接口 | `/api/v1/open` | `Authorization: Bearer <key>.<secret>`（或 `X-Vela-Key` / `X-Vela-Secret`） | 外部系统 |
| 回调 | `/api/v1/approvals/lark/callback` | 共享密钥（`Authorization: Bearer` 或 `?secret=`）+ 可选 IP 白名单 | 审批服务 |

一律 HTTP 200，业务结果在包体里：`{ code, msg, data }`（`0` 成功、`42200` 命令被拦截转审批、
`42800` 需二次验证、`42900` 登录频控、`40300` 无权、`40301` IP 不在白名单……完整码表见契约文件开头）。
无鉴权的只有 `GET /healthz`（`{status:ok}`）、`/openapi.yaml`、`/docs`。`GET /api/v1/gateway/stats`
给出最近 512 次请求的 p50 / p95 与生产拦截计数；**没有** Prometheus `/metrics`。

- **在线接口文档**：`GET /docs`（本地 http://localhost:8080/docs ）—— Swagger UI，带 **Authorize** 与
  **Try it out**，`#/tag/operation` 深链可直接分享。资源是 **vendored 进二进制**的（`internal/handler/swaggerui`，
  gzip 后约 415KB，Apache-2.0，LICENSE 随文件放），**不走 CDN**：断网机器上照常打开，这也是网关最常见的部署环境。
  契约本身从工作目录 `docs/openapi.yaml` 读，打包时要带上。Try it out 打的是真接口，对生产实例执行前想清楚。
- **完整契约**：`backend/docs/openapi.yaml`（运行时 `GET /openapi.yaml`）。**全部 136 个操作都在里面**
  （107 条路径）—— 由 `TestOpenAPICoversEveryRoute` 静态守着：新增路由没写进文档，测试直接失败；
  文档里写了不存在的路由，也会被 `TestOpenAPIDocumentsNoGhostRoutes` 挑出来。每个操作的 `summary`
  带守卫标注，形如 `[perms · admin]`、`[scope release:create]`，回答"我能不能调"。
- **外部系统对接**：`docs/开放接口对接文档.md` —— 怎么拿凭据、幂等怎么算、状态怎么轮询、
  各个错误码代表什么、最小接入清单。契约说不清的都在那里。

## 测试与质量

- **后端**：`go test ./... -timeout 20m` —— 以 **httptest 黑盒回归网**为主
  （`backend/internal/bootstrap/` 下 148 个测试文件，启动完整应用实跑 HTTP 接口，覆盖判定链、
  多语句、审批链、审计链、脱敏、导出上限、执行窗口、会话安全等），另有引擎方言 / 口令脱敏 /
  规范审查等单元测试。
  bootstrap 包每个用例都会启动一次完整应用并灌种子数据，整包约 12 分钟，**超过 `go test`
  默认的 10 分钟包超时**，所以上面那条命令带了 `-timeout`；不带会在跑完前被判超时失败。
- **前端构建**：`npm run build` = `tsc --noEmit` 类型检查 + Vite 打包，**按路由懒加载分包**
  （17 个页面各自成块，只想看一眼审批的人不必先下载终端与 xterm）。`npm run type-check` 单独跑类型检查。
- **前端约定**：不写 `forwardRef`（ref 是普通 prop）；不手写 `useMemo` / `useCallback`（交给 React Compiler，
  除非 profiler 证明必要）；`useEffect` 必须返回清理函数 —— StrictMode 下会双调用，xterm / WebSocket /
  定时器的泄漏在那里暴露。
- **服务端状态一律归 TanStack Query**，只有真正属于客户端的才进 Zustand。把列表塞进客户端 store 会得到
  两份真相，而它们分叉时的表现是「刷新一下就变了」。

### 两套前端

`frontend/` 是当前实现（React 19）。`frontend-vue/` 是被它取代的 Vue 3 实现，**留在仓库里**作为对照与回退：
它功能更全（CSV 批量导入导出、批量巡检、库归属、连接页的检索与分组），React 版尚未补齐这些，
清单见 `.scratch/` 与 GitHub issue。两边连同一个后端，可以同时起：React 在 5173，Vue 在 5174。

Vue 版自带 218 个单元测试（`cd frontend-vue && npm run test:unit`，Playwright runner 跑 `src/lib/*` 的纯逻辑
与词条、结构检查）与 5 个浏览器 e2e。React 版的纯逻辑从那里原样移植，测试尚未搬过来。
