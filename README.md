# Vela 数据库管理网关 (DP DB GATEWAY)

面向 DBA 与运维团队的统一数据库访问网关：所有数据库操作经 Web 终端 / 脚本 / 异步任务 /
数据导出四条通道下发，由网关按**三层策略**（菜单权限 → 能力矩阵 → 高危命令字典）逐语句
实时判定 —— 放行、拦截或转审批；审批通过后由网关代执行。全程写入防篡改审计哈希链，
可经 Webhook / 飞书外推。支持真实连接 MySQL、PostgreSQL、Oracle、SQLite 等多引擎实例。

```
db-gateway/
├─ backend/     Go + Gin + GORM 后端（REST + WebSocket；风险引擎/RBAC/审批/审计哈希链/多引擎真实执行）
├─ frontend/    Vue 3 + TS + Vite 前端（深色 Vela 设计系统，中英双语，xterm.js 真终端）
├─ docs/        PRD / 前后端开发文档 / 交互原型 / ADR / 外部审批对接指南
├─ deploy/      systemd unit + 环境变量模板
├─ build.sh     一键打包前后端（默认交叉编译 linux/amd64，产出版本化 tar.gz）
└─ docker-compose.yml  本地 MySQL 8 + Redis 7（可选）
```

## 功能总览

### 三层风险判定 · 环境/分层模型

- 判定链：`菜单权限 → 能力矩阵(角色×能力×分层) → 高危命令字典(命令×分层)`，外加严格模式
  （拦截无 WHERE 的 DELETE/UPDATE）。EXPLAIN 独立成档（`EXPLAIN` 只读、`EXPLAIN ANALYZE` 按真实执行判）。
- **分层标签（tier）承载规则，环境（environment）归属实例**：内置五个分层 —— `prod` 生产、
  `staging` 预发布、`uat` 演练、`gli` 法务、`dev` 开发；可自建环境并挂到任一分层，新分层自动
  克隆规则。同一 `DROP` 在 PROD 分层拦截转审批、在 DEV 直接放行。
- **多语句整批判定**：批量粘贴 / 堆叠语句（`SELECT 1; DELETE …`）逐条判级取最严格结论，
  预检、同步执行、异步执行三条路径一致；工单聚合展示全部命中规则。
- 按引擎方言判定（MySQL / PostgreSQL / Oracle / MongoDB 语法差异），注释剥离防绕过。

### Web 终端（xterm.js 真终端）

- WebSocket 流式执行（不可用自动回退 REST），psql/mysql 风格元命令（`\dt` `\d` `\l` `\x`
  `\G` `\conns` `\c <db>` 等），实例树按 环境 → 类型 → 实例 组织，支持搜索与点击切换。
- 结果网格 / 垂直显示 / 列宽截断提示，SQL 实测耗时，会话日志（含审计标注）一键导出。
- 快捷脚本：常用 SQL 存为片段，`Alt+1…9` 一键键入 —— 与手工输入走同一判定通道。
- 命中审批规则时弹出提交卡（必填原因），生成审批单 `AP-xxxx` 与审计 ID。

### 审批

- 多步审批链 + 超时策略（自动拒绝 / 自动升级 / 继续等待，后台定时扫描），自审开关，
  列表分页 + 单号直查；通过后由网关**代执行**并回填结果。
- **外部飞书审批（审批魔方）**：高危命令推送飞书交互卡片，回调驱动执行；回调带签名校验 +
  IP 白名单，外发内容全量脱敏。见 `docs/external-approval-setup.md` 与 ADR 0003。

### SQL 脚本

- 上传 `.sql` 管理 / 在线查看，逐语句扫描判级（按可配置的扫描基准分层）；检出高危则整脚本
  转审批 —— 审批单引用已上传文件（校验哈希），通过后逐语句代执行；全安全脚本直接逐条执行并逐条审计。

### 异步执行 · 数据导出

- **异步执行**：30–60min+ 的长语句/存储过程后台跑，流式收集 `RAISE NOTICE` 进度日志，
  执行前过同一判定链；超时可配（默认 90min）。
- **异步导出**：仅允许单条只读查询（写操作/写文件子句一律拒绝），结果流式写出为 ~100MB
  分卷、AES-256 加密 zip（带 UTF-8 BOM，Excel 中文不乱码），按任务发放解压口令；
  行数 / 字节 / 执行超时上限均为运行时设置（系统设置 · 网关），失败任务不遗留孤儿文件。

### 变更发布流水线（CI/CD）

- **流程可自定义**：一条流程 = 有序阶段列表，阶段类型有 `规范审查 / 人工审批 / 备份回滚点 /
  执行变更 / 执行后校验 / 人工确认 / 结果通知`；可按分层限定流程（如"开发自助发布"只对 DEV 生效），
  可设默认流程。内置两条模板，管理员在「流程」页拖动增删改。
- **发布单以 pipeline 形式展示状态**：每个阶段独立记录 `待开始 / 执行中 / 等待处理 / 已完成 /
  失败 / 已跳过`、耗时、日志与审查结果；点阶段看详情，人工确认阶段可在页面上放行。
- **发布不是执行旁路**：执行阶段**下发前再判一次**三层闸门 —— 发布单可能在审批里停了几小时，
  期间字典、实例归属、发起人角色都可能变；判定按语句下发那一刻的规则算，且逐条写审计（挂发布单号）。
- 审批阶段复用既有审批单与审批链（飞书 / 审批魔方 / 控制台四个入口都算数）；审批**通过本身不执行**，
  执行仍由执行阶段完成 —— 否则同一变更会被应用两次。网关重启时：`running` 判失败（执行结果未知，
  不重跑）、`waiting` 原样保留、`pending` 重新入队。

### 开放接口（外部系统提单）

- **一个外部系统一把凭据**（`Authorization: Bearer <key>.<secret>`），在【系统设置 · 开放接口】签发，
  绑定一个**服务账号** —— 该账号的角色决定这个系统能发布到哪些实例、什么变更要走审批，审计行记
  `actor=服务账号 / operator=API:<凭据名>`。可按凭据配 IP 白名单、权限范围（建单 / 查询 / 预检）、随时停用或吊销。
  明文密钥只在签发时回显一次（库里只有 bcrypt 哈希）。
- **提单**：`POST /api/v1/open/releases`，JSON 传 `sql`、`script`（或 `scriptBase64`），
  或 `multipart` 直传文件 `-F file=@upgrade.sql`；实例与流程都可以用**名字**寻址。脚本落盘并记录摘要，
  执行阶段重新读文件并校验哈希——审查过的字节和执行的字节是同一份。
- **幂等**：带上你自己的单号 `externalRef`，重试返回同一张升级单（数据库唯一索引兜底，并发重试也不会下发两次）。
- **查询与预检**：`GET /api/v1/open/releases/{relNo}` 拿各阶段状态与日志；
  `POST /api/v1/open/sql-review` 只做规范审查不建单，用作 CI 合并前门禁；
  `GET /api/v1/open/instances`、`/open/pipelines` 供集成方查可用实例与流程名。
- 走的是**同一条流水线**：同样的流程模板、规则库、审批链、执行前复判与审计链。开放接口只是一扇门，
  不是第二条执行通道。

### 数据库规范审查（MySQL / TiDB / DWS / Oracle）

- **34 条内置规则**，覆盖 DML、DDL、表结构、命名、索引、安全、性能七类，按**方言**作用域生效：
  TiDB 禁外键、DWS 建表必须 `DISTRIBUTE BY`、Oracle 用 `VARCHAR2` 而非 `VARCHAR`、
  MySQL 强制 InnoDB + utf8mb4，通用规则如"建表必须有主键""新增 NOT NULL 列必须给 DEFAULT"
  "UPDATE/DELETE 必须带 WHERE"。
- 规则的**级别（拦截 / 警告 / 提示）、开关、参数、文案**都在库里，控制台即改即生效；升级只补新增
  规则，不覆盖运维已经调过的策略。可自建正则规则（编码自动加 `custom.` 前缀）。
- 判的是"**写得对不对**"，与高危命令字典判的"**危不危险**"分开；结论只被发布流水线的审查阶段消费
  （`error` 级命中是否卡发布由流程配置决定），终端执行链路不受影响。上线前可在「审查」页自查。

### 审计

- 每条审计 `hash = SHA256(prev_hash + payload)` 构成防篡改哈希链（唯一约束防分叉），
  记录环境 + 分层**双快照**；命令中的口令语法全引擎脱敏。
- 按风险 / 时间范围（24h / 7 天 / 30 天）服务端过滤，分页，CSV 导出；涉及表列表化展示，完整命令入详情。

### 权限与账号

- 角色 × 菜单开关 × 能力矩阵三态（放行 / 审批 / 拒绝）在线编辑；高危命令字典逐分层指定生效等级。
- 能力维度：`SELECT / INSERT·UPDATE / DDL / GRANT / 管理连接 / 审批 / EXPLAIN / 发起发布单`。
  最后一个（`release`）管的是**能不能发起发布**，与语句本身能不能跑是两个问题：可以做到"开发自助发布、
  预发布必须走审批、生产一律不许外部发起"，而不必把 `DDL` 在生产整个关掉（那会连带堵死终端和审批通道）。
  三态在这里读作:放行 / 必须走含审批阶段的流程 / 不允许发起。升级时按各角色**同分层的 `write` 等级**回填，
  行为与升级前一致，且每个格子都有实际存在的行（不是"查无此行=放行"的默认值）。
- 菜单开关新增「变更发布」（`pipeline`，发布单页与流程页共用）；规范审查页挂在「Web 命令行」下 ——
  上线前自查是写变更的一部分，不该是另一项特权。
- 管理员建号（设初始密码即激活）、邀请用户、成员增删与搜索；实例按标签限定可访问角色。

### 会话与安全

- 会话 TTL、空闲自动锁定、TOTP MFA（自助绑定 / 强制开关 / 生产操作步进验证按连接记忆宽限期）、
  登录 IP 白名单（默认关，放行 loopback）；JWT 密钥与连接口令加密密钥解耦，支持 JWT 轮换。
- 连接口令 AES-GCM 静态加密；实例维护态限制下发并审计。

### 系统设置（运行时生效，免重启）

网关策略 / 执行与异步超时 / 导出上限与超时 / 审批链与超时策略 / 会话与 MFA / IP 白名单 /
Webhook（HMAC-SHA256 签名 + 指数退避重试）/ 飞书通知 / 外部审批对接，均落库持久化。

### 启动自检：审批人

每次启动会检查"这些审批环节到底还有没有人能批"，命中就打 WARN 日志（不阻止启动）：

| 情形 | 后果 |
|---|---|
| 角色没有成员，或成员**全是服务账号** | 工单根本建不出来（服务账号登录不了控制台，无法审批） |
| 链上**恰好一个人**且未开自审批 | 工单建得出来，但由他本人发起的**永远没人能批** |
| 启动那一刻已经卡住的存量待办 | 现在就已经没人能处理 |

第二条是最容易漏的：角色有成员、审批链建得出来、工单也创建成功，每一层校验都"通过"，
然后两人控制让它们一张都批不掉——单子静静堆在待办里，不报错也不推进。**上线后请看一眼
这几行日志**：

```
WARN 审批人自检: 默认审批链(DBA 负责人) severity=deadlock
     problem=链上只有 Lin Wei 一个人能批。两人控制下，由他本人发起的工单将没有任何人可以审批
     fix=为该角色再加入一名真人成员；若确为单人运维，可在「设置」中打开「允许自审批」
```

两条出路：给该角色**再加一名真人**（推荐，两人控制才成立），或在「设置」中打开
**允许自审批**（单人运维的逃生门；它只解除"自己不能审自己"，**不会**把人放上审批链）。

自检只看启动那一刻的快照，之后堆积的卡单它不会知道——它是上线检查项，不是监控。

## API

三套鉴权面，别混用：

| 面 | 前缀 | 鉴权 | 谁在调 |
|---|---|---|---|
| 控制台 | `/api/v1` | `Authorization: Bearer <JWT>` | 登录的人 |
| 开放接口 | `/api/v1/open` | `Authorization: Bearer <key>.<secret>` | 外部系统 |
| 回调 | `/api/v1/approvals/lark/callback` | 共享密钥 | 审批服务 |

一律 HTTP 200，业务结果在包体里：`{ code, msg, data }`（`0` 成功、`42200` 命令被拦截转审批、
`42800` 需二次验证、`40300` 无权……完整码表见契约文件开头）。

- **在线接口文档**：`GET /docs`（本地 http://localhost:8080/docs ）—— Swagger UI，带 **Authorize** 与
  **Try it out**，`#/tag/operation` 深链可直接分享。资源是 **vendored 进二进制**的（`internal/handler/swaggerui`，
  gzip 后约 425KB，Apache-2.0，LICENSE 随文件放），**不走 CDN**：断网机器上照常打开，这也是网关最常见的部署环境。
  Try it out 打的是真接口，对生产实例执行前想清楚。
- **完整契约**：`backend/docs/openapi.yaml`（运行时 `GET /openapi.yaml`）。**全部 110 条路由都在里面** ——
  由 `TestOpenAPICoversEveryRoute` 静态守着：新增路由没写进文档，测试直接失败；文档里写了不存在的路由，
  也会被 `TestOpenAPIDocumentsNoGhostRoutes` 挑出来。每个操作的 `summary` 带守卫标注，形如
  `[perms · admin]`、`[scope release:create]`，回答"我能不能调"。
- **外部系统对接**：`docs/开放接口对接文档.md` —— 怎么拿凭据、幂等怎么算、状态怎么轮询、
  各个错误码代表什么、最小接入清单。契约说不清的都在那里。

## 测试与质量

- 后端：`go test ./... -timeout 20m` —— 以 **httptest 黑盒回归网**为主（`backend/internal/bootstrap/` 下 80+
  测试文件，启动完整应用实跑 HTTP 接口，覆盖三层判定、多语句、审批链、审计链、脱敏、
  导出上限、会话安全等），另有引擎方言 / 口令脱敏等单元测试。
  bootstrap 包每个用例都会启动一次完整应用并灌种子数据，整包约 11 分钟，**超过 `go test`
  默认的 10 分钟包超时**，所以上面那条命令带了 `-timeout`；不带会在跑完前被判超时失败。
- 前端：`npm run build` = `vue-tsc` 类型检查 + Vite 打包 + vue-i18n 严格模式构建期预编译
  （非法文案直接构建失败）。
