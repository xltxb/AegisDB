# Vela 数据库管理网关 (DP DB GATEWAY)

面向 DBA 与运维团队的统一数据库访问网关：所有数据库操作经 Web 终端 / 脚本 / 异步任务 /
数据导出 / 发布流水线 / 开放接口下发，由网关**逐语句实时判定** —— 放行、拦截或转审批；
审批通过后**由人回来自己执行**，审批这一下不碰数据库（ADR 0010）。全程写进哈希链审计表，**并且可以当场重算校验**，
可经 Webhook / 飞书外推。支持真实连接 MySQL、PostgreSQL、Oracle、SQLite 等多引擎实例。

```
db-gateway/
├─ backend/     Go + Gin + GORM 后端（REST + WebSocket；风险引擎/RBAC/审批/审计哈希链/多引擎真实执行）
├─ frontend/    Vue 3 + TS + Vite 前端（Vela 设计系统，明暗双主题，中英双语，xterm.js 真终端）
├─ docs/        PRD / 前后端开发文档 / 交互原型 / ADR / 四份数据库规范 / 接口文档
├─ deploy/      systemd unit + 环境变量模板
├─ build.sh     一键打包前后端（默认交叉编译 linux/amd64，产出版本化 tar.gz）
└─ docker-compose.yml  本地 MySQL 8 + Redis 7（可选）
```

## 快速开始

### 一键启动（Windows，最省事）

双击项目根目录的 **`start-dev.bat`** —— 自动在两个窗口分别拉起后端（PostgreSQL 存储库，需本机 Docker 容器 `vela-store-pg`，端口 5437）与前端（Vite），
然后浏览器打开 http://localhost:5173 。
（也可单独双击 `backend\run-pg.bat` 或 `frontend\run-dev.bat`；不想装 PG 就双击 `backend\run-sqlite.bat`，零依赖。）

### 手动启动

```bash
# 后端（默认 APP_ENV=dev → SQLite，写 ./vela-gateway.db，自动迁移 + 引用数据）
cd backend && go run ./cmd/server            # 监听 127.0.0.1:8080，健康检查 GET /healthz

# 前端
cd frontend && npm install && npm run dev    # http://localhost:5173（代理 /api 到 :8080）
```

前端开发端口**钉死在 5173**（`vite.config.ts` 的 `strictPort`）：被占用时直接报错退出，
不会自己挪到 5174。挪号的代价是浏览器书签、e2e 脚本、同事手里的地址全指向上一轮遗留的旧
服务，而那行"端口已改"的提示没人会去读。

生产路径（MySQL 8）见下文【生产部署】与 `DEPLOY.md`。

## 功能总览

控制台共 17 个菜单页：总览 · 终端 · 导出 · 上传 · 后台执行 · 发布 · 流程 · 审查 · 审批 ·
项目 · 配置 · 规则 · 分层 · 班车 · 权限 · 审计 · 设置。每页由菜单开关按角色收敛。

### 风险判定 · 环境/分层模型

- 判定链：`菜单权限 → 能力矩阵(角色×能力×分层) → 高危命令字典(命令×分层) → 无 WHERE 拦截(分层)`。
  四层规则**都按分层存**：最后一层拦截不带 WHERE 的 DELETE/UPDATE，2026-09 前它是一个全局开关，
  于是无法只对 dev 关掉（迁移 0030 起改为按分层，开关在【分层】页）。EXPLAIN 独立成档：`EXPLAIN` 只看计划、按只读判；
  而**会真的执行**被包住语句的那些形式按真实执行判 —— `EXPLAIN ANALYZE`／英式拼写
  `ANALYSE`、选项表里的 `(ANALYZE …)`、以及 DWS/GaussDB 的 `EXPLAIN PERFORMANCE`。
- **分层标签（tier）承载规则，环境（environment）归属实例**：内置五个分层 —— `prod` 生产、
  `gli` 法务、`staging` 预发布、`uat` 演练、`dev` 开发；可自建环境并挂到任一分层，新分层自动
  克隆规则。同一 `DROP` 在 PROD 分层拦截转审批、在 DEV 直接放行。
- **多语句整批判定**：批量粘贴 / 堆叠语句（`SELECT 1; DELETE …`）逐条判级取最严格结论，
  预检、同步执行、异步执行三条路径一致；工单聚合展示全部命中规则。
- 按引擎方言判定（MySQL / PostgreSQL / Oracle / MongoDB 语法差异），注释剥离防绕过。
- 判定结论以**机器可读的规则引用**（`code` + 参数）回传，界面按当前语言渲染；服务端同时给出
  中文原文作为兜底，两边不会各说各的。

### 总览

登录落地页（不再直接进终端）。从前进来直接就是连着生产库、光标在等你敲字的提示符 ——
把唯一能改动真实数据的地方当默认页，等于每次开工都先站到闸门里面。

这一页汇总：待我审批的工单、等我执行的通过单与停在人工闸上的升级单、当前开着的执行窗口、
实例概况、近期审计与网关状态。**不新增任何接口，也不新增任何权限面** —— 每块数据都是用户
本来就能自己去拉的那一个接口，卡片按 `auth.menus` 收敛，各卡片并发加载且各自失败各自算
（一块取不到不该让整页空掉）。

### Web 终端（xterm.js 真终端）

- WebSocket 流式执行（不可用自动回退 REST），psql/mysql 风格元命令（`\dt` `\d` `\l` `\x`
  `\G` `\conns` `\c <db>` 等）。
- **一批语句、审批单、审批过的脚本、发布内容**在一条**专用连接**上执行：整批同一个会话（`SET`、
  `BEGIN … COMMIT`、临时表连得上），执行期间不被连接池换掉、也不占终端共用的池（每台实例 3 条）；
  执行完当场断开释放。终端的单条语句仍走连接池。超时 / Ctrl+C 照旧按每条语句的时限取消（MySQL 系另开
  临时连接发 `KILL QUERY`）。TCP 保活由驱动默认开启（15 秒），长语句执行期间不会被防火墙当空闲连接掐掉。
- 实例树按 环境 → 类型 → 实例 组织；**搜索覆盖实例、库与表**。库表不随连接列表下发 ——
  每台实例要单独连过去 introspect 一次，所以探查过的立刻可搜，其余的由人点「全部探查」
  显式发起（并发受限、进度可见），界面上写清还有几台没搜。PostgreSQL 的表按库单列一笔
  （它的 `information_schema` 是按库的）。
- Oracle 终端认得 SQL*Plus 的习惯：`SET SERVEROUTPUT ON` 回车即生效（只对当前标签页），
  之后执行的匿名块、`EXEC` 会在结果后面回显 `DBMS_OUTPUT`（每次至多 2000 行）；粘贴的整段里
  的 `SET SERVEROUTPUT ON / OFF` 对后面的语句按顺序生效。`SHOW SERVEROUTPUT` 查看开关；
  `SET LINESIZE / PAGESIZE / DEFINE …` 这类显示设置明确提示"已忽略"，不发给数据库。
  PL/SQL 块可以逐行手敲：块里的分号、`END LOOP;` 都不会提前提交，敲到最外层的 `END;`
  或单独一行的 `/` 才执行。
- MySQL 终端认得 mysql 客户端命令，回车即执行、不用分号：`pager` / `\P` 在**浏览器里**过滤结果
  （不起 shell；内置 `less more cat grep egrep fgrep head tail wc sort uniq`，可用 `|` 串起来，
  如 `pager grep -v Sleep | wc -l`；交给过滤器的是 mysql 样式的 `+---+` / `|` 表格，不截断长值），
  `nopager` / `\n` 取消；`tee [文件名]` / `\T` 开始另记一份输出，`notee` / `\t` 停止并下载
  （与「导出日志」同一条路径：口令打码、写导出审计）；`status` / `\s` 看当前连接与设置；
  `rehash` 刷新补全缓存。`system`、`source`、`delimiter` 等浏览器里做不了的，明确提示，不发给数据库。
- Oracle 的对象树第二层是 **OWNER（schema）**，不是服务名；终端里切 schema 之后触发的
  工单、审计、后台任务记的都是那个 schema，批准后执行会切回同一个地方。
- Oracle 程序包可**右键下载**：得到 `.pck` 文件，内容是包头加包体，每段以 `/` 收尾，
  拿到 SQL*Plus 或 PL/SQL Developer 里可以直接执行重建。按住 Ctrl/⌘ 单击可多选，
  Shift 单击可连选，右键菜单里也能全选本组，选中多个时打成一个 zip。
  单击包名仍然是查看源码。每次下载都会记一条「导出」审计，写明下载了哪些包。
- 结果网格 / 垂直显示 / 列宽截断提示，SQL 实测耗时，会话日志（含审计标注）一键导出。
  终端与结果表之间可上下拖分；左右两栏可折叠，宽度可拖（执行上下文默认收起），
  拖动不会把终端挤到断行 —— 中间那栏有下限。
- 快捷脚本：常用 SQL 存为片段，`Alt+1…9` 一键键入 —— 与手工输入走同一判定通道。
- 命中审批规则时弹出提交卡（必填原因），生成审批单 `AP-xxxx` 与审计 ID。

### 业务方数据查询

- 给业务方（运营、财务、客服等）开放**只读**的生产数据查询。能查哪些库只由**查询授权**决定：
  外部审批系统（审批魔方）审批完，调开放接口下发（`grant:read` / `grant:write`，见《开放接口对接文档》第九节）。
  授权按人、按库，有到期时间；按 `externalId` 幂等（同单号重试原样返回，新单号更新，旧单号拒绝）；
  每个凭据只看得到、只撤销得了**自己下发的**授权。被授权人没有账号时自动建号，只挂「业务查询」角色。
- 只挂「业务查询」角色的账号**不设本地口令**（后台建号、重置密码、口令登录都会被拒），
  业务方待 SRD 授权登录上线后经 SRD 进入网关。
- 只有管理员标记为「业务查询源」的实例能被授权，约定指向**从库**、使用只读库账号。
  也可以在【数据源 · 编辑】里给实例配一个**从库**：配了之后数据查询（执行、导出、表清单）都由从库提供，
  终端、审批执行、发布仍走主库；从库连不上时自动回落主库，结果与审计里注明。
- 业务方只看得到「数据查询」一页。每条查询：单条只读语句（拒绝写、加锁、INTO、读文件等函数，
  拒绝反斜杠转义的引号 `\'` —— 各引擎理解不一，是绕过判定的常见手法），不能引用同实例的别的库或系统库；
  最外层补 LIMIT（默认 1000 行，上限 10000；自带的 LIMIT 更大会被改小，不是数字直接拒绝）；在**只读事务**里
  执行，库端时限默认 30 秒（上限 300），超时自动取消（MySQL 系另发 `KILL QUERY`）；结果一律按
  【设置 · 敏感字段】脱敏，与终端、导出同一套规则。可以 EXPLAIN 看执行计划（Oracle 写
  `EXPLAIN PLAN FOR <查询>`，网关代为取出计划、不在 PLAN_TABLE 留东西）。经子查询 / UNION / WITH 给敏感字段改名的查询
  （打码按列名比对，兜不住这种形态）直接拒绝并写审计。
- 限流：并发默认每人 2 条、每实例 5 条；可设每人每天次数上限（默认不限，次日零点恢复）。超出回 `42900`。
- 拒绝与失败都带机器可读的原因（`data.reasonRef` / `data.errorRef`，code + args），前端据此多语言展示。
- 每次执行写审计，写明依据的是哪条授权、返回多少行、是否截断、耗时；被拒绝的语句同样留痕。
- **导出**：全局开关（默认关）加上授权里的「允许导出」都开，业务方才能把结果下载为 CSV
  （至多授权的行数上限，永远脱敏，防公式注入），写导出审计。
- **管理**：【权限 · 查询授权】是授权总表，可按人、部门、实例、库、状态筛选，管理员可立即撤销；
  【设置 · 数据查询】调全局值（默认 / 上限行数、时限、授权最长有效期、并发、每人每天次数、导出总开关），
  保存时整体校验并写审计。

### 表结构对比

- 【结构对比】页：左右各选「实例 + 库」（同一引擎族：MySQL 系 / Oracle / PostgreSQL·DWS），比较同一个库在
  不同环境（如 PROD 与 UAT）的表结构。两边**实时读系统目录**，只读结构、不碰数据。
- 比较表 / 视图是否存在、表注释、列（类型、可空、默认值、注释、顺序）、主键、索引；`int(11)` 与 `int`、
  `'0'` 与 `0` 这类写法差异不算差异，可勾选忽略列顺序 / 注释 / 索引名。
- 结果按「只在左 / 只在右 / 结构不同」分组，点开看左右对照；可导出 Markdown / CSV。
- 左右可以是同一实例的两个库（PG / DWS 还可指定同库的两个 `schema`）。
- 库名（PG / DWS 还有 `schema`）是可输入筛选的下拉（实时读实例上的库 / 库里的 schema，不列系统库），列表里没有的也能直接用输入的名字；读不到列表时退回手填。
- 左右两个实例都要有访问权限；菜单默认给平台管理员与 DBA 负责人。每次对比写"读"审计，左右是两个实例时各记一条。

### 生产大表在线加 / 删索引（在线变更，ADR 0011）

- 生产实例（分层要求 MFA）上，估算 ≥ 100 万行或数据 + 索引 ≥ 1 GB 的表（「系统设置 → 网关策略」可改），
  单个 `ADD INDEX` / `DROP INDEX` / `CREATE INDEX` / `DROP INDEX … ON` 不再直接执行，自动改走在线变更：
  影子表 + 分块拷贝 + binlog 重放 + 原子切换，期间业务照常读写。
- **终端**：先跑前置检查（binlog 配置、主键、外键 / 触发器、磁盘、残留表……），通过则生成一张必须审批的
  「在线变更」工单；审批通过后在审批页点「执行」（再查一遍后启动），详情里看进度，可暂停 / 继续 / 中止。
  一批语句里混着它的会被要求单独提交。
- **发布流水线**：预检列出将以在线变更执行的语句与前置检查结论；没有审批阶段的流程不收单；执行阶段就地
  迁移，阶段日志实时显示进度；中止发布 = 中止迁移。
- 大表上在线变更做不了的 DDL（加列、唯一索引、一句多个变更……）照原路径审批执行，但终端与工单上醒目
  提示"可能长时间锁表"。切换成功后保留原表为 `_表名_del`，由 DBA 择时手动删除。
- 网关重启时进行中的迁移判失败并清理影子表，不续跑；部署需执行迁移 0049。

### 审批

- 多步审批链 + 超时策略（自动拒绝 / 自动升级 / 继续等待，后台定时扫描），自审开关，
  列表分页 + 服务端搜索（单号 / 实例 / 库 / 命令 / 发起人）。
- **通过不执行任何命令** —— 通过后通知发起人，由人回到本页点「执行」，一张单只能执行一次
  （`WHERE executed_at IS NULL` 兜底）；执行前会再判一次规则。
  **执行权不限发起人本人**：够得到那台实例、能力矩阵也放行的同事可以接手（ADR 0010 的
  2026-09-09 修订 —— 需求要的是"值班的人能接手"，而值班的常常正是审批人）；别人替你跑了，
  发起人会收到通知。升级单、执行窗口单、导出单都不走这条路，它们各有各的执行方。
- 列表上**提交时间与执行时间各占一列**。批准只是解锁了一次执行，真正落到库上往往要等业务
  低峰 —— 事后对时间线要看的是后者。没跑过的行给一个短横，不拿提交时间充数。
- 待办行右侧独立一列放操作（审批 / 拒绝 / 撤回 / 执行），详情单独入口。**最终状态以数据库上
  那次执行的结果为准**：目标库拒绝了这条语句，单子就显示失败，而不是「已执行」；
  详情里能看到那次执行的输出与影响行数（迁移 0032 起单独存 `exec_status`，不与审批状态合并）。
  命令还在库上跑时显示「执行中」（页面自动刷新到出结论），不是点了执行就算完成；网关在执行途中
  重启的，启动时判失败并写明「结果未知，请到库上核实」，不重跑。
- **外部飞书审批（审批魔方）**：高危命令推送飞书交互卡片，回调驱动执行；回调带签名校验 +
  IP 白名单，外发内容全量脱敏。见 `docs/external-approval-setup.md` 与 ADR 0003。

### 执行窗口（「班车」，ADR 0015）

维护车次里一晚上几十条 DDL 逐条等人批不现实，而「提前把规则改松、事后忘了改回去」比没有
审批更糟 —— 没人知道门还开着。执行窗口把那个口头约定变成系统里可查、可审计、**到点自动
关上**的东西。

- **只把 `approve` 降为 `allow`**。能力矩阵判 `deny` 的仍然 `deny`：只读角色不会因为到了
  凌晨两点就能写生产库。风险等级也不降 —— 窗口改变的是流程，不是事实。
- **按库开**，库名必填：一台实例底下往往混着不同业务的库，放开面越小越好。
- 放宽发生在**判定函数内部**，不是各个执行入口 —— 否则新加一条路就要记得也放宽，
  而那类遗漏的表现是「同一条语句在终端免审批、在后台执行却要审批」。
- 所有失败方向都朝严：读不到窗口表 / 时区解析不出来 / 库名为空 / 定义写不通 → 不生效或当场拒绝。
- 窗口放行的每条命令，审计 `operator` 字段指回是**哪个窗口**放的。
- **回看**：一扇门开着的那几个小时里到底跑了什么，单独一页列出来，被这扇门放行的那几条
  （本来需要审批）单独标出。内容**不按人收窄** —— 免审批的门免掉的是审批，也就免掉了签字
  的人，一份只剩"我自己跑的那两条"的回看读起来和"这扇门没出什么事"一模一样。打得开这一页
  的是：持有班车菜单的人，或监督角色（管理员 / 负责人 / 审计员）。

### SQL 脚本

- 上传 `.sql` 管理 / 在线查看，逐语句扫描判级（按可配置的扫描基准分层，ADR 0014）；
  检出高危则整脚本转审批 —— 审批单引用已上传文件（校验哈希），发起人执行时重新读文件、
  校验哈希、逐语句重判再逐条执行；全安全脚本直接逐条执行并逐条审计。
- **同一个脚本不会被点两次跑两遍**：下发期间整个扫描弹窗被遮罩盖住，连关闭都不行 ——
  按钮变灰只挡得住「再点一次执行」，挡不住「关掉重新扫一遍」。下发有界超时，遮罩必然散去。

### 异步执行 · 数据导出

- **异步执行**：30–60min+ 的长语句/存储过程后台跑，流式收集 `RAISE NOTICE` 进度日志，
  执行前过同一判定链；超时可配（默认 90min）。
- **异步导出**：仅允许单条只读查询（写操作/写文件子句一律拒绝），结果流式写出为 ~100MB
  分卷、AES-256 加密 zip（带 UTF-8 BOM，Excel 中文不乱码），按任务发放解压口令；
  行数 / 字节 / 执行超时上限均为运行时设置（系统设置 · 网关），失败任务不遗留孤儿文件。

### 敏感字段脱敏（ADR 0009）

脱敏落在**结果离开网关之前**，不是前端打码 —— 后者等于把明文完整发到浏览器再请它不要显示，
而那份数据在被"隐藏"之前已经躺在浏览器缓存、沿途反代日志和前端错误上报里了。
整个网关只有两处把行读出来（终端结果与导出），两处都过同一层。端到端测试直接断言
**原始响应体里明文一个字节都不能出现**。

它的**边界**写在代码注释里，也写在这里：打码是拿选择列表的文本去比对的，所以一个铁了心
要拿数据的人总能构造出映射不回去的表达式（`SELECT x FROM (SELECT id_card AS x FROM t_user) s`
是最简单的一种）。真正的边界是**不给这张表的访问权限** —— 标签与角色才是那道墙，这里只是
让日常查询不至于把身份证号刷在屏幕上。

**导出这条路不一样，所以单独收紧**：它产出的是一份可以带走的 CSV，而且正是"敏感导出需
审批"这条控制要拦的东西。一条查询若**既触及带规则的表、又用了派生表 / UNION / CTE**，
导出一律转为敏感导出去走审批 —— 这里不去猜列血缘（要猜就会猜错，而错的方向是漏），
只保守地问一句"有没有可能绕过"。

`hash` 这种打码方式**加部署盐**：无盐的 SHA-256 对低熵值等于没打码，手机号一共 11 位、
身份证号结构公开，一台笔记本几分钟就能把全空间跑完再反查回去。加盐之后同一套部署里同一个
值仍然稳定（"这两行是同一个人"看得出来），换一套部署则对不上 —— 那是对的，两套部署之间
本来就不该能靠打码值做关联。

### 变更发布流水线（CI/CD）

- **流程可自定义**：一条流程 = 有序阶段列表，阶段类型有 `规范审查 / 人工审批 / 备份回滚点 /
  执行变更 / 执行后校验 / 人工确认 / 结果通知`；可按分层限定流程（如"开发自助发布"只对 DEV 生效），
  可设默认流程。内置两条模板，管理员在「流程」页拖动增删改。
- **发布单以 pipeline 形式展示状态**：每个阶段独立记录 `待开始 / 执行中 / 等待处理 / 已完成 /
  失败 / 已跳过`、耗时、日志与审查结果；点阶段看详情，人工确认阶段可在页面上放行。
- **发布不是执行旁路**：执行阶段**下发前再判一次**闸门 —— 发布单可能在审批里停了几小时，
  期间字典、实例归属、发起人角色都可能变；判定按语句下发那一刻的规则算，且逐条写审计（挂发布单号）。
- 审批阶段复用既有审批单与审批链（飞书 / 审批魔方 / 控制台四个入口都算数）；审批**通过本身不执行**，
  执行仍由执行阶段完成 —— 否则同一变更会被应用两次。网关重启时：`running` 判失败（执行结果未知，
  不重跑）、`waiting` 原样保留、`pending` 重新入队。
- **收单预检**（ADR 0017）：外部系统提单时先把目标对象查一遍，结论标明来源（实时查 / 用缓存，
  缓存的把同步时间摆出来）；没做的检查照样列出来，不是从结果里消失 —— 留白会被读成通过。

### 项目

数据库与升级单的归属，自己的一页。它从「配置」页搬出来，因为读者不是同一批人：配置实例的是
DBA，按项目跟进升级单的是业务线上的人。页面只做归属与跟进（项目增删改、名下有多少库多少张单，
点进去落到按项目筛过的升级单列表）；把库归到哪个项目仍在「配置」页做 —— 那件事要对着实例
底下的库来点。

### 开放接口（外部系统提单）

- **一个外部系统一把凭据**（`Authorization: Bearer <key>.<secret>`），在【设置 · 开放接口】签发，
  绑定一个**服务账号** —— 该账号的角色决定这个系统能发布到哪些实例、什么变更要走审批，审计行记
  `actor=服务账号 / operator=API:<凭据名>`。可按凭据配 IP 白名单、权限范围（建单 / 查询 / 预检）、随时停用或吊销。
  明文密钥只在签发时回显一次（库里只有 bcrypt 哈希）。
- **提单**：`POST /api/v1/open/releases`，JSON 传 `sql`、`script`（或 `scriptBase64`），
  或 `multipart` 直传文件 `-F file=@upgrade.sql`；实例与流程都可以用**名字**寻址。脚本落盘并记录摘要，
  执行阶段重新读文件并校验哈希——审查过的字节和执行的字节是同一份。
- **幂等**：带上你自己的单号 `externalRef`，重试返回同一张升级单（数据库唯一索引兜底，并发重试也不会下发两次）。
- **查询与预检**：`GET /api/v1/open/releases/{relNo}` 拿各阶段状态与日志；
  `POST /api/v1/open/sql-review` 只做规范审查不建单，用作 CI 合并前门禁；
  `GET /api/v1/open/instances`、`/open/pipelines` 供集成方查可用实例与流程名。
- 走的是**同一条流水线**：同样的流程模板、规则库、审批链、执行前复判与审计链。开放接口只是一扇门，
  不是第二条执行通道。

完整对接步骤见 **`docs/开放接口对接文档.md`**。

### 数据库规范审查（MySQL / TiDB / DWS / Oracle）

- **87 条内置规则**，按公司四份规范（`docs/` 下 MySQL / TiDB / Oracle / DWS）重写，每条标注
  **规范分级与出处**（高危 / 强制 / 建议；规范未覆盖的标「平台内置」）——被拦下来的人能回去读原文。
  覆盖 DML、DDL、表结构、命名、索引、安全、性能七类，按**方言**作用域生效：
  TiDB 禁外键、DWS 建表必须 `DISTRIBUTE BY`、Oracle 用 `VARCHAR2` 而非 `VARCHAR`、
  MySQL 强制 InnoDB + utf8mb4，通用规则如"建表必须有主键""新增 NOT NULL 列必须给 DEFAULT"
  "UPDATE/DELETE 必须带 WHERE"。
- 规则的**级别（拦截 / 警告 / 提示）、开关、参数、文案**都在库里，控制台即改即生效；升级只补新增
  规则，不覆盖运维已经调过的策略。可自建正则规则（编码自动加 `custom.` 前缀）。
- 判的是"**写得对不对**"，与高危命令字典判的"**危不危险**"分开；结论只被发布流水线的审查阶段消费
  （`error` 级命中是否卡发布由流程配置决定），终端执行链路不受影响。上线前可在「审查」页自查。

### 审计

审计表要回答同一句话的六个部分：**什么时候、谁、从哪台机器、对哪个库、做了什么、结果如何**。

- **一行的内容**：时刻 · 操作人 + **来源 IP**（迁移 0041）· 实例（按分层着色）+ 库.表 ·
  命令原文 · 事件类型（拦截 / 审批 / 执行 / 登录）· 增删改查 · 风险 · 结果 · 授权它的工单号 ·
  环境与分层**双快照** · 链式校验值。命令中的口令语法全引擎脱敏后才入库。
- **来源 IP** 取自 gin 的 `ClientIP()`：只在配置过的可信代理后面才认 `X-Forwarded-For`
  （默认一台都不信），客户端伪造不了 —— 与 IP 白名单读的是同一个值。actor 回答"谁"，它回答
  "人在哪"：同一个账号从两个网段各删过一次数据，只看 actor 是一模一样的两行。
- **筛选**：时间（近 1 小时 / 24 小时 / 7 天 / 30 天 / 自定义区间）· 实例 · 事件类型（多选）·
  增删改查（多选）· 风险 · 操作人姓名、邮箱或 IP 模糊搜。全部在服务端筛 —— 列表是分页的，只筛当前页
  会对一条躺在第三页的记录回答"没有"。CSV 导出跟着同一组条件走。
- **可见性**：有监督角色（管理员 / 负责人 / 审计员）的人看得见所有人的行，其余人只看得见自己的。

#### 哈希链与校验

每一行的 `hash = SHA256(前一行 hash ‖ 本行内容快照)`，`prev_hash` 上有唯一索引，链在数据库层
分不了叉。改掉中间任何一行，它之后的每一行都对不上 —— 改一行的代价是重写整条尾巴。

链**可以当场重算**，三个入口共用同一套判断：

```bash
./vela-gateway verify-audit            # 全表;链断了退出码 2,可直接挂进巡检
./vela-gateway verify-audit -limit 5000
```

另有 `GET /api/v1/audit/verify`（验最近 5000 行，限监督角色）与审计页上的「校验哈希链」按钮。

审计**写入**失败也有一个出口：`GET /healthz` 里的 `auditWriteFailures`，**非零就该告警**。
它计的是"动作已经发生、审计行没写成"的次数。这种时候不回滚也不阻断 —— 动作已经落在目标
库上了，回滚不了，而把调用方变成失败只会让人以为没执行、再跑一遍，在写操作上那是更坏的
结果。所以取舍是：动作照常返回，但这件事**不允许悄无声息**。原先只有一行错误日志，在日志
量大的机器上等于没有。
只报**第一处**对不上的行 —— 链是前后咬合的，第一处断掉之后后面每一行都会跟着对不上，报"坏了
几行"只会让人以为损坏面很大。三种结论要人做的事不同：

| 结论 | 含义 |
|---|---|
| `content` | 这一行的内容被改过 |
| `link` | 前驱哈希接不上上一行 —— 中间有行被删除或插入 |
| `gen` | 它按比前面更老的键集才算得过 —— 像是抹掉了较新字段再重算 |

载荷的键集是**分代**的（迁移 0039 的 `event`、0040 的 `action`、0041 的 `ip` 各加一代），
老行只能按它写下那天的键集重算，所以校验时从新到老逐代试，并要求代不倒退。

**它挡得住什么、挡不住什么**：载荷是裸 SHA-256、算法公开，拿得到数据库写权限的人可以把整条
尾巴重算一遍而链照样自洽（白盒审计 L-12）。所以它挡的是"顺手改一行"，挡不住有备而来的重写。
要挡后者，得给载荷加密钥（HMAC），或者把链尾定期外推到网关自己改不了的地方 —— 而**这条链
最有用的用法本来就发生在网关之外**：网关自己的库是可写的，Webhook 推到 SIEM / 数据湖的那份
是只进不出的（`raw_payload` 里带着 `hash` 与 `prevHash`），两边对一下才叫核对。
`service.AuditPayloadGen` / `AuditGenRange` 为此导出，给链外的核对工具直接用。

### 权限与账号

- 角色 × 菜单开关 × 能力矩阵三态（放行 / 审批 / 拒绝）在线编辑；高危命令字典逐分层指定生效等级。
- 能力维度：`SELECT / INSERT·UPDATE / DDL / GRANT / 管理连接 / 审批 / EXPLAIN / 发起发布单`。
  最后一个（`release`）管的是**能不能发起发布**，与语句本身能不能跑是两个问题：可以做到"开发自助发布、
  预发布必须走审批、生产一律不许外部发起"，而不必把 `DDL` 在生产整个关掉（那会连带堵死终端和审批通道）。
  三态在这里读作：放行 / 必须走含审批阶段的流程 / 不允许发起。升级时按各角色**同分层的 `write` 等级**回填，
  行为与升级前一致，且每个格子都有实际存在的行（不是"查无此行=放行"的默认值）。
- 菜单开关含「变更发布」（`pipeline`，发布单页与流程页共用）与「执行窗口」（`execwindow`）；
  规范审查页挂在「Web 命令行」下 —— 上线前自查是写变更的一部分，不该是另一项特权。
- 管理员建号（设初始密码即激活）、邀请用户、成员增删与搜索；实例按标签限定可访问角色。
- **在线用户**（仅管理员，权限页的一个分页）：此刻登录着的会话、来源 IP、浏览器、登录时间、最近操作
  （不含页面自动轮询，超过 10 分钟没操作标"空闲"）、开着的终端及是否正在执行。3 分钟内有请求或开着
  终端算在线；退出登录 / 停用 / 重置口令后立即消失。只记在网关内存里（重启清空，多副本时各看各的）。
  用户列表的「最近活跃」同时改为真实时间（每人每分钟至多写一次库）。

### 会话与安全

- **SRD 授权登录(公司 SSO,可选)**:只做认证 —— SRD Portal 回答"你是谁",网关照旧回答"你能干什么",
  判定链不变。登录页「使用 SRD 授权登录」跳到 SRD 完成 Lark 授权,SRD 在公司父域写 `CS-Token` 后跳回;
  网关服务端解出其中的 JWT,调 SRD 的 `userinfo` 换出邮箱,按邮箱映射到网关用户;网关里没开通这个邮箱的账号就拒绝,
  登录页弹窗提示"无权限访问",由管理员在【权限 · 用户】开通后再登录。在【系统设置 · 会话与安全】里开关,即改即生效、升级不丢。
  存量账号在**第一次经 SRD 登录、邮箱对上时自动绑定**:绑定的人只能走 SSO(管理员保留口令应急),
  没用过 SRD 的人照常用口令;管理员可在【权限 · 用户】解绑。网关须部署在 SRD Cookie 的父域下。
  出问题时关掉设置页开关即回到口令登录;进不去设置页时用部署层总闸 `sso.disabled: true` /
  `VELA_SSO_DISABLED=1`(重启生效)。详见 `DEPLOY.md` 第 7 节。

- 会话 TTL、空闲自动锁定、TOTP MFA（自助绑定 / 强制开关 / 生产操作步进验证）、
  登录 IP 白名单（默认关，放行 loopback）；JWT 密钥与连接口令加密密钥解耦，支持 JWT 轮换。
- **步进验证的宽限期绑定到单个会话**，不是绑到人。每个 token 签发时带一个唯一 `jti`，
  宽限键是 `用户:代次:jti:实例` —— 原先键在用户级的会话代次上，于是同一个人的并发会话
  共享同一条记录：受害者在自己浏览器里验过一次，一个被盗的 token 在宽限期内对同一台实例
  也跟着免验，而它根本没证明过持有第二因子。拿不到会话标识时**每次都要求验证**。
- 终端 WebSocket 是长连接，也是执行通道：**每条命令前重新比一次 token 到期时间**、
  重新读一次账号状态与菜单。只在握手时验一次，等于会话 TTL 对终端不生效。
- 账号**只有 `active` 放行**。改回 `invited` 或任何中间态都会让已发出的 token 立刻失效 ——
  管理员做那一下，想的正是"这个人现在不该再进来了"。
- 连接口令、**TOTP 种子**均 AES-GCM 静态加密；实例维护态限制下发并审计。
  （种子明文存着，等于把 MFA 降级成一个稍长的口令字段：任何一条读到用户表的路径 ——
  备份、只读从库、一次 `SELECT *` —— 都能把第二因子整个带走。）
- 开放接口按来源 IP 对**认证失败**计数（10 次 / 5 分钟 → 锁 5 分钟），判定在 bcrypt
  **之前**：那一步故意慢，而它在任何鉴权之前，谁都能打。成功即清零，正常集成碰不到。
- 安全响应头（`X-Content-Type-Options` / `X-Frame-Options` / `Referrer-Policy`，终止 TLS 时加 HSTS）；
  仅信任显式配置的反向代理，客户端无法靠 `X-Forwarded-For` 伪造来源 IP。

### 系统设置（运行时生效，免重启）

网关策略 / 执行与异步超时（终端命令默认 30 秒；**审批单执行单独一项**，默认 1 小时、最长 24 小时，
大表 DDL 走审批时按它算）/ 导出上限与超时 / 审批链与超时策略 / 会话与 MFA / IP 白名单 /
Webhook（HMAC-SHA256 签名 + 指数退避重试；按「增删改查」与环境订阅，环境留空 = 全部）/ 飞书通知 / 外部审批对接 / 开放接口凭据，均落库持久化。

## 生产部署

```bash
./build.sh          # 前端构建 + 后端交叉编译 linux/amd64 + 版本化 tar.gz（含部署速查）
```

单二进制同时提供 API 与前端 SPA，内嵌 41 个 SQL 迁移；子命令 `version` / `migrate` / `init` /
`verify-audit`。服务端**只产出 Linux 二进制** —— 在 Windows 工作站上构建时也一样，那台机器
不是部署目标。归档里的二进制权限 `0755` 是**写进 tar 的**而不是读构建机文件系统的（Git Bash 下
`chmod` 对 NTFS 是空操作），打包脚本自己会校验这一条，不满足就直接失败。

打包前还有一道闸：逐条走 `docs/simulated-paths.md` 里登记的每一条模拟路径，确认关掉模拟之后
它们给的是明确的拒绝而不是编出来的数据。跑不过就不出包 —— 来由是一次线上误判，「批量巡检」
把 88 台实例全报成「可连」，因为那条探测从第一笔提交起就是个 `sleep(120ms); return true` 的桩。

本项目的生产目录是 **`/opt/db-gateway`**（包里 systemd 模板写的是 `/opt/vela-gateway`，
安装时按实际路径改）。完整步骤（MySQL 准备、迁移、初始化管理员、systemd 托管、TLS、
环境变量一览）见 **`DEPLOY.md`** 与打包产物内的 `README-DEPLOY.md`。

### 手工跑子命令时，环境变量要自己加载

生产的 DSN 与密钥来自 `vela.env`，而那个文件是 **systemd 通过 `EnvironmentFile=` 注入给服务
进程**的 —— 你在 root shell 里手工跑 `./vela-gateway migrate` 时它并不存在，配置会回落到
`configs/config.yaml` 里那条本地默认 DSN，于是报 `dial tcp 127.0.0.1:3306: connection refused`。

```bash
cd /opt/db-gateway
set -a; . ./vela.env; set +a     # VELA_MYSQL_DSN / VELA_JWT_SECRET / APP_ENV
./vela-gateway migrate
```

`verify-audit` 同理 —— 它也要连库。

> `EnvironmentFile=-/...` 前面那个 `-` 表示**文件不存在就静默跳过**。照模板装完却忘了建
> `vela.env`，服务会照常起来、一个环境变量都没有，然后以同样的方式连本地 3306：起得来、
> 连不上，而且不报配置错误。

### 升级已有环境的顺序

备份数据库 → 停旧进程 → `./vela-gateway migrate` → 起新进程 → `./vela-gateway version` 确认版本。
反过来做，新二进制会对着旧表结构跑；迁移之后也不要单独回滚二进制（旧代码按旧列名查询，列已经
不在了）。这类失败朝"关"的方向 —— 规则查不到就拒绝 —— 不会变成放行，但会是一场故障。

### 启动自检：审批人

每次启动会检查"这些审批环节到底还有没有人能批"，命中就打 WARN 日志（不阻止启动）：

| 情形 | 后果 |
|---|---|
| 角色没有成员，或成员**全是服务账号** | 工单根本建不出来（服务账号登录不了控制台，无法审批） |
| 链上**恰好一个人**且未开自审批 | 工单建得出来，但由他本人发起的**永远没人能批** |
| 启动那一刻已经卡住的存量待办 | 现在就已经没人能处理 |

第二条是最容易漏的：角色有成员、审批链建得出来、工单也创建成功，每一层校验都"通过"，
然后两人控制让它们一张都批不掉——单子静静堆在待办里，不报错也不推进。**上线后请看一眼
这几行日志**：

```
WARN 审批人自检: 默认审批链(DBA 负责人) severity=deadlock
     problem=链上只有 Lin Wei 一个人能批。两人控制下，由他本人发起的工单将没有任何人可以审批
     fix=为该角色再加入一名真人成员；若确为单人运维，可在「设置」中打开「允许自审批」
```

两条出路：给该角色**再加一名真人**（推荐，两人控制才成立），或在「设置」中打开
**允许自审批**（单人运维的逃生门；它只解除"自己不能审自己"，**不会**把人放上审批链）。

自检只看启动那一刻的快照，之后堆积的卡单它不会知道——它是上线检查项，不是监控。

### 上线后：给审计链建一个基线

```bash
cd /opt/db-gateway && set -a; . ./vela.env; set +a
./vela-gateway verify-audit
```

记下行数，之后定期跑（退出码 2 就告警）。它也值得在**从备份恢复出来的库**上跑一遍 ——
拿今天的库和上周的备份各验一次，是这条链最有用的用法。

若报某一行对不上，先看断点落在哪儿：**很老的行**多半是分代键集没覆盖到（不是有人动过），
把输出发给维护者扩表即可；断点落在近期的行上才值得紧张。

## API

三套鉴权面，别混用：

| 面 | 前缀 | 鉴权 | 谁在调 |
|---|---|---|---|
| 控制台 | `/api/v1` | `Authorization: Bearer <JWT>` | 登录的人 |
| 开放接口 | `/api/v1/open` | `Authorization: Bearer <key>.<secret>` | 外部系统 |
| 回调 | `/api/v1/approvals/lark/callback` | 共享密钥 | 审批服务 |

一律 HTTP 200，业务结果在包体里：`{ code, msg, data }`（`0` 成功、`42200` 命令被拦截转审批、
`42800` 需二次验证、`40300` 无权……完整码表见契约文件开头）。

四份东西，各答一个问题：

| 文档 | 回答什么 | 给谁 |
|---|---|---|
| `GET /docs`（Swagger UI） | 这条接口现在长什么样、能不能当场试一下 | 联调中的人 |
| `backend/docs/openapi.yaml` | 完整契约：全部 141 条路由 / 111 条路径 / 140 个操作 | 写客户端的人、生成代码的工具 |
| `docs/控制台接口说明.md` | 控制台这一面按业务分组怎么用、各自的守卫是什么 | 接控制台 API 的人 |
| `docs/开放接口对接文档.md` | 怎么拿凭据、幂等怎么算、卡住了怎么办、错误码各是什么 | 外部系统集成方 |

- **在线接口文档** `GET /docs`（本地 http://localhost:8080/docs ）带 **Authorize** 与
  **Try it out**，`#/tag/operation` 深链可直接分享。资源是 **vendored 进二进制**的
  （`internal/handler/swaggerui`，Apache-2.0，LICENSE 随文件放），**不走 CDN**：断网机器上
  照常打开，这也是网关最常见的部署环境。它只在**本地开发**环境挂载 —— 生产上把完整路由表
  交给任何一个未鉴权的访客，是送给攻击者的一份地图（issue 35）。Try it out 打的是真接口，
  对生产实例执行前想清楚。
- **契约不会漂**：三个静态测试守着 —— 新增路由没写进文档 `TestOpenAPICoversEveryRoute` 失败；
  文档里写了不存在的路由 `TestOpenAPIDocumentsNoGhostRoutes` 挑出来；带守卫的路由若没在
  `summary` 里标出守卫（形如 `[perms · admin]`、`[scope release:create]`）
  `TestOpenAPIDeclaresGuards` 失败 —— "我能不能调"是读者的第一个问题，而答案从路径上看不出来。

## 测试与质量

- **后端**：`go test ./... -timeout 30m` —— 以 **httptest 黑盒回归网**为主
  （`backend/internal/bootstrap/` 下 164 个测试文件，启动完整应用实跑 HTTP 接口，覆盖判定链、
  多语句、审批链、审计链与校验、脱敏、导出上限、执行窗口、会话安全等），另有引擎方言 /
  口令脱敏 / 规范审查等单元测试，全仓 824 个测试函数（238 个测试文件）。
  bootstrap 包每个用例都会启动一次完整应用并灌种子数据，整包 **20 分钟上下**（本机实测
  1200s，机器越忙越久），远超 `go test` 默认的 10 分钟包超时，所以上面那条命令必须带
  `-timeout`；不带会在跑完前被判超时失败，而那个失败长得很像真的挂了。
- **前端构建**：`npm run build` = `vue-tsc` 类型检查 + Vite 打包 + vue-i18n 严格模式构建期预编译
  （非法文案直接构建失败）。
- **前端单元测试**：`npm run test:unit`（225 个用例，Playwright runner 跑 `src/lib/*` 的纯逻辑：
  终端行编辑器、结果渲染的控制字符、会话日志脱敏、导入表解析、规则文案、词条一致性等）。
  它用 `tsconfig.unit.json` 把 `@/locales` 指向一个测试替身 —— 裸 Node runner 既读不了 `.json5`
  也没有 `localStorage`，而那次失败炸的是**收集阶段**：整套一个用例都不执行。替身只替掉加载，
  词条与 vue-i18n 都是真的，因为这里的断言看的正是用户会读到的那段中文。
- **前端 e2e**：`npm run test:e2e`（14 个 spec、63 个用例，Playwright 驱动真实浏览器，
  接口全部打桩）。默认在 5174 起一个独立的 dev server，不会碰你手上开着的 5173。
