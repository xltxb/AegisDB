03 路由与菜单权限

Routing & Menu Guard

每个路由声明 meta.menuKey,与后端返回的 menus 对应。守卫在导航时校验登录态与菜单可见性,无权限重定向到总览,一个菜单都没有的账户弹回登录页。部分页面用 meta.gate 复用另一个菜单的权限 —— 导出 / 上传 / 后台执行 / 规范审查都挂在terminal 下(上线前自查是写变更的一部分,不该是另一项特权),发布单与流程共用 pipeline。总览带 meta.home,在闸门之前放行。

05 核心模块实现要点

Module Notes

5.1 Web 命令行终端

三栏布局:左侧分层树、中间 xterm 终端、右侧风险检查面板。提交命令时先调风险预检,命中高危则打开拦截/提交卡,不直接执行;否则经 WebSocket 下发由网关代执行并回显。

async function onSubmit(sql: string) {
  const r = await api.risk.check({ connectionId, sql })   // 三层判定
  if (r.requiresApproval) {
    interceptModal.open({ sql, ...r })                  // 填原因 → 提交审批
  } else {
    terminalWs.send({ type: 'exec', sql })             // 网关代执行
  }
}

5.2 SQL 脚本上传与扫描

读取 .sql 文件后 multipart 上传至 POST /scripts/scan;后端返回逐条语句风险与统计,前端渲染扫描报告。检出高危则主按钮变"提交审批后执行"。

5.3 权限矩阵与菜单权限

CapabilityMatrix.vue 单元格点击循环 allow→approve→deny,按角色与环境保存;MenuAccess.vue 逐菜单开关。保存调用 PUT /roles/:id/capabilities 与 /menus。

5.4 高危字典三态

字典按环境(PROD/STAGING/DEV)Tab 切换,命令徽标点击循环 拦截/审批/放行,调用 PATCH /risk-commands/:name。PROD 配置驱动终端与脚本扫描。

5.5 审批待办

列表区分"待我审批 / 全部";卡片展示命令、发起人、原因、审批链;通过/拒绝调用对应接口并乐观更新状态。

07 三层权限控制(前端)

Client-side Authorization

前端仅做展示层收敛(藏入口、灰按钮),真正的拦截以后端为准:

  • 菜单层:路由守卫 + 动态侧栏,按 menus 渲染。
  • 能力层:v-permission="'ddl:prod'" 指令按能力矩阵禁用/隐藏操作。
  • 命令层:提交前 /risk/check 决定放行/审批/拦截。
// directives/permission.ts
export const vPermission = {
  mounted(el, { value }) {
    if (!useAuthStore().can(value)) el.setAttribute('disabled', 'true')
  }
}

10 构建、规范与交付

Build & Conventions
  • 规范:ESLint + Prettier + vue-tsc 类型检查;组件 PascalCase,store/composable useXxx。
  • 类型:types/ 与后端 docs/openapi.yaml 一一对应;契约由后端的 TestOpenAPICoversEveryRoute 双向守住,前端不再做一次运行时校验。
  • 构建:Vite 按路由懒加载分包;环境变量 VITE_API_BASE / VITE_WS_BASE。
  • 测试:npm run test:unit 用 Playwright runner 跑 src/lib 的纯逻辑与词条/结构检查(210 例);npm run test:e2e 5 例走浏览器。拦截→审批→执行的整链由后端 httptest 覆盖,不在浏览器侧重复搭。
