# ADR 0023:SSO 改为标准 OIDC,移除 SRD Portal 私有协议

- 状态:已采纳
- 日期:2026-11-26
- 相关:#171、`backend/internal/service/sso.go`、`sso_oidc.go`、`backend/internal/handler/sso.go`、DEPLOY.md 第 7 节

## 背景

SSO 原先对接公司 SRD Portal 的私有协议:SRD 在公司父域上写 `CS-Token` Cookie(自定义字母表的 base64
包着一个 JWT),网关从 Cookie 里解出 JWT,再以 Bearer 调 SRD 的 userinfo 换邮箱。代价:

- 网关必须部署在 `CS-Token` 所在父域之下,否则浏览器根本不带这个 Cookie。
- Cookie 编码是从 SRD 线上前端包里逆出来的;SRD 一升级换字母表,登录就整体失效。
- 换任何别的身份服务都要重写,而公司内外的身份服务普遍支持标准 OIDC。

## 决定

### 一、只保留标准 OIDC:授权码流程 + PKCE,SRD 私有协议整体移除,不并存

- `GET /api/v1/auth/oidc/start`:生成 state、nonce、PKCE(S256)校验串,302 到身份服务。
- `GET /api/v1/auth/oidc/callback`:核对 state,服务端换 token,按 JWKS 验 ID Token(签名、iss、aud、exp、
  nonce),取邮箱。
- `POST /api/v1/auth/sso`:用回调留下的登录结果换网关会话。映射、账号状态、管理员 TOTP、绑定规则全部沿用。
- 依赖 `github.com/coreos/go-oidc/v3` 与 `golang.org/x/oauth2`(Go 里事实标准的实现),版本选在仍支持
  `go 1.23` 的范围内,不抬高工具链要求。

### 二、流程状态放浏览器,由网关加密,不放服务端内存

state / nonce / verifier 与"验过的身份"各放一枚 HttpOnly、SameSite=Lax 的 Cookie,内容用
`crypto.SealFor` 加密并带过期时间:密钥是静态存储密钥按用途派生的子密钥,用途串同时作为 GCM 附加数据。
不直接用 `EncryptSecret`,是因为那把钥匙也加密连接口令、webhook 密钥这类**明文可由用户选定**的值 ——
否则一段精心构造的口令密文就能冒充一张登录结果。流程与登录结果的用途也不同,彼此打不开。

网关可能多副本部署,回调未必落在发起的那一台上;放在浏览器里就不需要共享存储。Lax 而不是 Strict:身份服务跳回来是一次跨站的顶层 GET。

### 三、回调不直接签会话

回调是一次浏览器跳转,没有地方问管理员要 TOTP(M8)。所以回调只验身份、写登录结果,跳回登录页;
登录页再 `POST /auth/sso` 换会话 —— 与原来 SRD 时代的"登录页换会话"同一个入口,错误码与前端处理不变。

### 四、只认已验证的邮箱

邮箱是网关认人的唯一依据。邮箱字段为标准的 `email` 时要求 `email_verified=true`(很多身份服务允许用户
自填邮箱);管理员改用别的字段(如 `upn`)即表示担保它是本人邮箱。ID Token 里没有邮箱时取 userinfo,
且 `sub` 必须与 ID Token 一致。

### 五、回调地址必填,不从请求推断

网关常在反向代理后面,从 Host / X-Forwarded-* 推出来的 scheme 与路径不可靠,而回调地址必须与身份服务里
登记的逐字一致。设置项「回调地址」必填、必须以 `/api/v1/auth/oidc/callback` 结尾;登录完成后跳回的
网关地址也由它推出(去掉这一段),因此网关挂在子路径下也成立。

### 六、和身份服务说话的客户端单独加固

不跟随跳转;拨号时拒绝链路本地、未指定与组播地址(云元数据,含 NAT64 包装),内网与本机放行
(身份服务部署在内网是常态);响应体限 1MB;发现文档里的各端点同样必须是 https(本地开发除外)。
发现结果缓存一小时,网络请求在锁外进行,刷新失败时沿用上一份。ID Token 有多个受众时要求 `azp`
是本应用。回调与登录接口共用按 IP 的频控。

## 后果

- 网关不再受父域限制,可以部署在任意域名下。
- 升级后旧的 `sso.baseUrl` / `sso.cookieName` 不再读取,SSO 按关闭处理(已绑定账号临时恢复口令登录),
  直到管理员配好 OIDC。绑定关系保留;没有口令的账号在配好之前登不进来(DEPLOY.md 第 7 节)。
- 部门不再从身份服务同步:OIDC 没有标准的部门声明,为一个展示字段引入可配置映射不值得。
- 登录页不再"进来就静默试一次":只有从回调回来(`#/login?sso=1`)才换会话。主动登出后因此不会立刻
  又登进去,原先为此加的 `aegisdb_sso_skip` 标记一并删除。
- 历史 ADR 与报告中提到 SRD 授权登录的地方保持原样,它们记录的是当时的事实。

### 已知边界(评审时记下,暂不处理)

- **只按邮箱认人,不锁 `(iss, sub)`。** 身份服务把一个邮箱回收后分配给别人,新主人会进到旧账号。
  锁定 `sub` 要加列并改绑定规则,留待另议;在此之前,离职要同时在网关里停用账号。
- **登录结果在服务端不是一次性的。** 成功后浏览器删掉它,但同一个值 5 分钟内可再换一次会话;
  它是 HttpOnly 的,泄露途径与会话 Cookie 相同。
- **兄弟子域可写 Cookie 的部署**下,理论上能把攻击者自己的登录结果塞进受害者浏览器(登录 CSRF)。
  需要攻击者控制同父域下的另一个站点。
- 邮箱字段换成 `email` 以外的声明时,网关不再要求已验证;Entra ID 的 `upn` / `preferred_username`
  在部分租户里可被改写,选用前确认它在你们的租户里不可由用户修改。
