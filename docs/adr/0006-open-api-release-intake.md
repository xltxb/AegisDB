# ADR-0006:开放接口 —— 外部系统提交 SQL 升级单

- 状态:已接受(2026-08-24)
- 相关:ADR-0005(发布流水线与规范审查)、迁移 `0020_api_client.sql`

## 背景

发布流水线做完之后,第一个需求是"别让人来控制台点":变更单来自 DevOps 平台、CI 流水线或
变更管理系统,SQL 或升级脚本就在那边,应该由它们直接提单。

难点不在于加几个 HTTP 路由,而在于**外部调用方没有主体**。网关的每一层都以"人"为轴:
能力矩阵按角色判、标签范围按用户判、PROD 的 MFA 策略按用户判、审计链按 actor 记账。
一条没有主体的调用通道,是一条**没有任何一层能判定**的通道。

## 决策

### 一、一个外部系统一把凭据,凭据绑定一个服务账号

`tbl_api_client`:key(公开)+ secret 的 bcrypt 哈希 + `user_id`(服务账号)+ 权限范围 +
来源 IP 白名单 + 启停。鉴权走 `Authorization: Bearer <key>.<secret>`。

没有采用"全局共享一把密钥"(即审批魔方回调那种做法),因为它同时丢掉三件事:

- **归属**:发布单是谁提的?共享密钥答不上来。
- **判定依据**:以谁的角色判这条变更?共享密钥没有角色。
- **可吊销性**:一把泄露,只能整体轮换,所有对接方一起断。

服务账号是显式参数,不给默认值。让凭据"图省事"绑管理员,等于把改任何实例的权力发给每一个
集成方 —— 这个参数存在的意义,就是让这件事在签发的那一刻被看见。

审计行因此有两个名字:`actor` 是服务账号(动作以它的身份执行),`operator` 是
`API:<凭据名>`(是这个系统要求的)。`AuditLog.Operator` 本来就是为"授权者不等于执行者"
准备的字段(EA4),这里是它的第二个用途。

### 二、开放接口是一扇门,不是第二条流水线

`/api/v1/open/*` 的每个写路径最终都落到 `submitRelease` —— 与控制台**同一个函数**。同样的
流程模板、同样的规则库、同样的审批链、同样的执行前复判、同样的审计链。

门上只加机器调用方真正需要的三件事:

1. **按名字寻址**。外部系统知道 `order-cluster` 与「标准发布流程」,不知道行 id。名字不唯一
   时报错而不是猜 —— 这里猜错的代价是变更打到了另一个库。
2. **脚本直传**。JSON 里的 `script` / `scriptBase64`(避免调用方 YAML 模板的转义 bug 变成
   被改坏的语句),以及 `multipart` 的 `file` 字段(`curl -F file=@upgrade.sql` 就是 CI 里
   的真实写法)。脚本落盘 + 记摘要,执行阶段重读文件并校验哈希,与脚本审批同一条路径。
3. **幂等**。外部系统会重试。

### 三、幂等键用 NULL 而不是空串,并且由数据库约束

`idem_key = "<client_id>:<external_ref>"`,唯一索引。字段可空且只有 API 单会写值:
NULL 在唯一索引里互不冲突,空串会 —— 否则每一张控制台发布单都会被判成前一张的重复。

用唯一索引而不是"先查后插",是因为并发的两次重试可以同时通过检查。插入撞键时回读那张已存在
的单返回给调用方:它要的是一张单,而系统里就是一张。

### 四、开放接口不挂控制台的 IP 白名单

`security.ipAllowlist` 回答的是"哪些办公网可以打开控制台"。把 CI runner 的出口段并进去,
等于为了让一台机器能提单而放宽了控制台的边界。凭据自带白名单,粒度对得上。

## 影响

- 新表 `tbl_api_client`;`tbl_release` 增加 `source / client_id / client_name /
  external_ref / idem_key`。
- 控制台【系统设置 · 开放接口】签发与吊销凭据;明文密钥只在签发响应里出现一次。
- 权限范围三档:`release:create` / `release:read` / `review:check`。只读看板不该拿到一把能
  在生产建变更的凭据。

## 未采纳

- **每单回调(callbackUrl)**:调用方给一个 URL、发布结束时回调。留待需要时再做 —— 现有
  Webhook 已经把审计事件推出去了,而每单一个任意 URL 是一片新的 SSRF 面,值得单独设计。
- **凭据直接持有角色**(不绑账号):等于在 RBAC 之外开出第二套权限模型,两套迟早会不一致。
- **允许改密钥**:轮换 = 新签一把 + 吊销旧的。就地改密钥会让正在用它的系统在某一刻毫无征兆
  地开始 401,而日志里看不出发生过什么。
