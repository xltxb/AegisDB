# ADR 0015:执行窗口(「班车」)

- 状态:已采纳
- 日期:2026-09-08
- 相关:`backend/internal/service/exec_window.go`、`exec_window_admin.go`、
  `internal/model/model.go`(ExecWindow)、`migrations/0031_exec_window.sql`

## 背景

定期维护和发版车次里,一晚上几十条 DDL 逐条等人批是不现实的:审批人被叫醒,或者干脆
提前把规则改松、事后忘了改回去 —— 后者比没有审批更糟,因为没人知道门还开着。

现实里的做法是提前约好一个时间段。这个功能把那个口头约定变成系统里可查、可审计、
**到点自动关上**的东西。

## 决定

### 它改的是流程,不是权限

窗口只把 `approve` 降为 `allow`。能力矩阵判 `deny` 的仍然 `deny` —— 只读角色不会因为
到了凌晨两点就能写生产库。

这是整个功能的安全边界。"免审批"和"有权限"是两件事,把它们混在一起,窗口就从"省掉一次
等待"变成了"临时提权",而后者没有任何东西能兜住。

风险等级也**不降**:它描述这条语句有多危险,窗口改变的是流程,不是事实。降级会让审计里
那条 DROP 看起来像一次普通查询。

### 按库开

不按实例,也不按分层。一台实例底下往往混着不同业务的库,而一次变更通常只动其中一两个。
放开面越小,窗口开着的那几个小时里能出的事就越少。

库名必填:空库名会让一个窗口悄悄覆盖整台实例。

### 放宽发生在判定函数内部

不是在各个执行入口。终端、异步执行、脚本执行、发布流水线、Oracle 编译,每一条都经过
`judge`。放在入口上就意味着"新加一条路时要记得也放宽",而这类遗漏的表现是"同一条语句
在终端免审批、在后台执行却要审批",用户完全看不懂。

`execJudged`(脚本逐条执行)绕过主判定自己算,所以它单独接了一次 —— 写这段时确实差点漏掉。

预检(`RiskCheck`)走的也是这里,所以终端不会先弹一个填审批理由的框、提交后才发现不用审批。
为此给预检接口补上了 `database` 参数:窗口按库开,不带库名就判不出窗口。

### 所有失败方向都朝严

- 读不到窗口表 → 当作没有窗口(照常审批)
- 时区解析不出来 → 该窗口不生效,而不是退回服务器时区
- 库名说不清(空)→ 不生效
- 写不通的定义 → 建的时候当场拒绝

最后一条尤其要紧:写坏的窗口有两种烂法,而它们不对等 —— 一种是永远不开(白配),另一种是
**开在没预料的时间**。所以宁可拒绝一个说不清的定义,也不替用户猜。

### 审计

窗口放行的每一条命令,在审计的 `operator` 字段里指回是哪个窗口放的。那个字段的语义正是
"当授权者不是操作者本人时,是谁授权的" —— 这里授权的不是人,是当时开着的那扇门。
`operator` 在审计链的哈希里,事后改不了。

开关窗口本身也进同一条链:开一扇免审批的门是一次权限变更,和改能力矩阵、改高危字典同级。

## 时间模型

两种共用一张表:

- `once` —— 起止时刻,用完即废。比的是绝对时刻,不涉及时区。
- `recurring` —— 固定时段反复生效,带 IANA 时区,可给整条班线设停运时刻。

时区存名字而不是偏移量:运维说的"凌晨两点"是他所在时区的两点,而网关可能跑在 UTC 上;
偏移量还会在夏令时切换时失真。

**跨午夜**是这里唯一需要小心的地方。`22:00-02:00` 的窗口,凌晨一点属于**前一天**发的那
班车,所以星期几要按"这班车是哪天发的"算。否则一个"仅周五"的窗口会在周五凌晨误开,而周六
凌晨反倒关着。单测专门钉了这一组。

## 界面上的"进行中"由后端算

`ExecWindow.Active` 是列表时用**与判定完全相同的** `windowCovers` 算出来的,不是前端重算。
跨午夜与时区换算在 TS 里再写一遍,两份实现迟早分叉,而分叉的表现是"界面说开着、网关说
没开" —— 而这扇门开没开,是运维当下要据以决策的事。
