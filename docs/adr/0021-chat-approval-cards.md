# ADR 0021:聊天审批卡片,网关主动连出去

- 状态:已采纳
- 日期:2026-11-26
- 取代:ADR 0003(外部飞书审批,已移除)
- 相关:`backend/internal/chat/`、`backend/internal/service/chat_*.go`、迁移 0065、ADR 0010、
  `docs/chat-approval-setup.md`、`.scratch/chat-approval-cards/PRD.md`

## 背景

ADR 0003 把审批卡片外包给公司自研的审批系统(审批魔方)。AegisDB 要成为通用产品,不能依赖它,对接已整体
移除(#137)。审批人仍然需要在聊天里直接通过 / 拒绝,而且要在没有公网入口的内网部署里也能用。

## 考虑过的做法

| | A 网关主动连出去 | B 平台回调网关 | C 卡片跳转确认页 |
|---|---|---|---|
| 收点击 | Lark 官方长连接;Telegram `getUpdates` 长轮询 | 公网 HTTPS 回调 | 打开 AegisDB 登录后批 |
| 要求 | 能访问外网 | 公网域名、证书、入口 | 审批人能打开网关 |
| 代价 | 一个机器人只能一个实例连;Lark 只支持自建应用 | 内网部署用不了;多一个能触发审批的公网入口 | 不是在卡片上直接批 |

选 A。B 与内网部署冲突,还多一个高危公网入口(0003 的回调正是审计里的 M-1);C 不满足在卡片上直接批。

## 决定

### 一、渠道只管收发,决定只有一个核心

`internal/chat` 与各渠道实现不引用 service / repository / model(有用例钉着)。点击最终走站内审批同一个
`DecideBlockFor` → `finalizeApproval`:同一套规则,第一个决定生效。**通过不等于执行**(ADR 0010):没有任何
卡片路径调用执行。`tbl_approval.decided_via` 记渠道,审计操作人写「姓名 (Lark)」。

### 二、身份靠一次性绑定码,不靠邮箱

本人登录后生成码(启用了 MFA 的先过一次),私聊发给机器人。绑定是**比会话活得更久的凭据**,所以:

- 码随机约 49 位熵、10 分钟、一次性、只存摘要;同一聊天账号 15 分钟错 10 次锁 15 分钟。
- 停用账号、改 / 重置口令、MFA 变更自动解绑,顺序是先作废会话再解绑。绑定与解绑通知本人并记审计。
- 绑定记着机器人标识,换了机器人旧绑定失效。只认私聊。
- 不设有效期。SSO 用户离职靠管理员在网关里停用账号;界面与文档写明。

### 三、按钮只带随机令牌

192 位令牌,库里只存摘要;不带单号(可预测)。点击时依次核对:令牌 → 点击者的聊天账号是这张卡片收件人的
有效绑定 → 在职真人 → 有「审批」菜单 → `DecideBlockFor`。查库出错一律什么都不改。

### 四、先落库、后台发;收敛靠扫描

建单只写 `queued` 行,发送与更新都由每 5 秒一次的扫描做,各最多 5 次。渠道出任何事都不影响建单、站内审批、
超时扫描。单子离开待审批有 7 条路,其中两条是仓储层直接改状态;不逐条挂钩子,扫「已发出、单子已不在
待审批」的行(与 `ResumeReleaseApprovals` 同理)。

### 五、内容

语句先 `sqlutil.RedactSecrets`。卡片上所有来自用户的文字都放进不解析标记的纯文本,看不见的字符显示成转义。
显示不全时卡片正文和确认框都写明,仍允许通过(用户的决定)。「是否显示全文」发卡时定下,随行存。

### 六、密钥不外泄

App Secret 加密存、不回显。REST 用手写的小客户端,不用 SDK 的:SDK 按 appId 在进程里缓存令牌、会跟跳转、
报错文本不归我们管。错误文本先去掉密钥、令牌、长连接票据再记日志或返回;panic 只记调用栈。出站只放行平台
主机,不跟跳转,不走环境变量代理(代理的报错会带出代理地址)。

## 后果

- 不需要公网入口;但一个机器人只能给一个网关实例用,多环境要多个应用。
- 用户 IP 白名单管不到卡片上的点击。
- 卡片内容会留在平台的服务器上。
- 飞书只能更新 14 天内的消息;发送是至少一次,超时重试可能多出一张失效的卡片。
- 引入 `larksuite/oapi-sdk-go/v3`(只用长连接与事件分发),二进制约大 5%。SDK 每条断开的连接会留下一个小协程。
- 只能经代理出网的部署用不了 Lark。
- 真实平台、国际版未验证,写在设置页与接入文档里。
- 迁移 0065 只增不删,回滚后新表闲置无害;回滚期间的账号变更不会解绑(接入文档第九节)。
