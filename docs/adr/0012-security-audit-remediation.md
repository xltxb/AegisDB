# ADR 0012:白盒安全审计的修复取舍(2026-09-02)

- 状态:已采纳
- 相关:`docs/白盒安全审计报告.md`(基线 `10b45c3`)

报告提了 2 High + 11 Medium + 18 Low。本文记的不是"修了什么",而是**哪些没照建议
改、为什么** —— 那部分才是以后会被人翻出来问的。

## 两条 High:核实属实,而且有一条比报告说的更宽

### H-1 异步通道判定原始串

确认。证据是代码自己的注释:同步 `Exec` 在 ER3 里白纸黑字写着"绝不可对原始串判定
—— 一个游离的前导分隔符会让动词解析落空,写操作就以只读身份跑掉了",而 `ExecAsync`
只在 `len(stmts) > 1` 时才拆。实测 `SplitStatements(";UPDATE …")` 恰好只拆出一条,
于是保留了对原串的判定 → 动词为空 → 归入 select → 只读角色在 PROD 写库。

修法:与 `Exec` 对齐,无条件拆分后判定。空输入直接拒绝。

**两条通道通往同一个执行器,判定就必须是同一套。** 这不是"补一个 if",是一条应当
成立的不变式。

### H-2 SET 的作用域识别

确认,并且**报告只说了一半**。逃逸正则 `^\s*SET\s+(GLOBAL|…)` 有两个洞:

1. `SET @@GLOBAL.read_only = 0` —— 作用域写在变量名上,SET 后紧跟的是 `@@`(报告点名)
2. `SET SESSION a=1, GLOBAL b=2` —— **正则锚定在开头**,逃逸词在第二个赋值上就漏掉
   (报告没提)

两条都会让 `SessionScoped` 误判为"只影响本会话",于是只需 select 能力就能关掉全局
只读、关掉 binlog 掩盖写入。

修法:不再锚定开头,在整条语句里找作用域标记,并识别 `@@GLOBAL.` 形式。宁可多认 ——
`SET @x = 'GLOBAL'` 会被判成逃逸、走原判定(按写处理)。多拦一条无害的会话设置,好过
放过一条改服务器的语句。

## 两条**没有照建议改**

### M-5:不禁"绑真人",只禁"绑管理员"

报告建议 `Create/Update 校验 Kind==service`。照做之后 **14 条测试全红**。

去查产品实际提供了什么:`ApiClientsPanel.vue` 的创建界面把**全部用户**列进选择器,
服务账号加 🤖 排在前面,真人账号照样可选并显示邮箱。**绑真人是有意提供的用法**,
不是疏漏 —— 把凭据挂在某个负责人名下,正是"每个集成方各自一把凭据"要的归属。

所以只挡最锋利的那一刀:**不能绑平台管理员**。差别在后果的量级 —— 绑普通成员,
凭据拿到的是那个人本来就有的权限,审计里写着他的名字;绑管理员则等于把一把能改权限
矩阵、建凭据、停用账户的钥匙,变成一个不经登录、不经 MFA 的身份,而 admin 恰恰是唯一
一个"权限大到审计归属也救不回来"的角色。

现有测试没有一处绑管理员,说明这条路本来就没人走。创建与换绑两个入口都堵 —— 只堵
创建等于没堵。

### M-4:不翻转"查无规则行 = 放行"

报告的第三条建议是"`capabilityLevelUnion` 对某角色该 tier 无任何 capability 行按
deny 处理"。**不采纳。**

"查无规则行 = 放行"是这套能力矩阵的**基础语义**,整个权限模型建立在它上面(见
`env-tier` 那一组设计)。翻转它不是修 bug,是重做权限系统,而且会让所有未配置的格子
在升级的那一刻同时变成拒绝。

报告指出的真实问题是**幽灵角色 id**:一个不存在的角色永远查无规则行,于是持有它的
用户每一格都读成放行。正确的解法是不让它进来,以及在权限计算入口滤掉它:

- `AddRoleMember` 校验角色存在(原先直接写成员表)
- `PatchUser` 的单角色路径补 `validateRoleIDs`(多角色路径本来就有)
- `EffectiveRoleIDs` 过滤掉不存在的 id —— 这条是兜底,历史数据里若已经躺着一个,
  光补入口是追不回来的

`existingRoles` 查询失败时保留原样:一次数据库抖动不该让所有人瞬间失去全部角色。
保留的是**真实存在过的** id 集合,不是把未知当成放行。

## 其余已修

| # | 修法 |
|---|---|
| M-1 | 有 task id 就必须匹配,**省略同样拒绝**(原条件两个都非空才比,省掉字段即跳过整条校验) |
| M-2 | 执行前补 `canAccessConn` + 维护态 + MFA;复判的 tier 改用**实时值**而非工单快照 |
| M-7 | 补三类脱敏:复制口令(`_password` 前无词边界)、conninfo 裸值、对象存储密钥 |
| M-9 | 控制台上传复用开放接口那套 15MB 上限与 `LimitReader`(原先按 `file.Size` 直接分配) |
| M-11 | 回调 operator 截断到列宽 —— 外部输入不该决定审计写不写得进去 |

M-2 值得单说:"已批准未执行"的工单目前不会过期(见 ADR 0010 记的那笔账),所以一张
上周批准的工单,在发起人标签权限被收窄、实例进维护态、MFA 被重置之后照样跑得掉。
**批准授权的是"这条命令",不是"绕过此后一切访问控制"。**

tier 从快照改实时也在这里:快照记的是"当时按哪一层判的",那是给人事后看的;而这一次
是真要下发,该按实例**现在**属于哪一层判。发布流水线的执行阶段一直用实时 tier,两条
路不该给出不同答案。

## 这份报告该怎么用

它的 High 两条核实后完全属实,M-1/M-2/M-4/M-7/M-9/M-11 也都属实 —— 静态审计在
"这段代码有没有这个缺陷"上很准。

但凡涉及**"这个功能该不该存在"**,它给不出答案:M-5 那条差点让我砍掉一个在用的能力。
报告自己在第七节写了"所有发现均为候选发现",这不是免责套话 —— 每一条都要回到产品
实际提供了什么去判断。
