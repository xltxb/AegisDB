# ADR 0024:数据查询权限可在网关内申请与开通

- 状态:已采纳
- 日期:2026-11-27
- 相关:#173、`backend/internal/service/query_grant_apply.go`、迁移 0066

## 背景

数据查询的授权只有一个来源:外部审批系统(当时是 SRD 服务中心)审批后调开放接口下发。网关内部既不能申请也不能
开通,数据查询页的「去申请权限」是一个写死为 SRD 申请页的外链。没有外部审批系统的部署,业务方无处申请。

## 决定

1. **申请方式是一个设置**:`bizQuery.applyMode` = `internal`(默认)/ `external`。external 时行为与以前相同
   (外链为 `bizQuery.applyUrl`,默认为空,不再内置任何公司的地址)。
2. **网关内申请走审批单**:申请生成一张新类型 `grant` 的审批单(`tbl_approval.query_grant_req_id` 指回申请),
   走默认审批链 —— 谁能批、超时、自审批、聊天卡片全部沿用审批单那一套,不长出第二套规则。申请记录
   (`tbl_query_grant_request`)不单独记状态,状态取自审批单,撤回、超时、驳回都不必再同步。
3. **批准前重新校验**:提交到审批之间,实例可能被取消标记、库可能没了、上限可能改小、导出可能关了。校验不过
   就不让批(批准接口说明原因,审批人应驳回),不出现"批准了却没有授权"的单子。实例此刻列不出库时同样
   不让批 —— 核实不了不等于还在(#179)。批准后生成 / 更新授权,来源
   记「网关审批」,外部单号为审批单号。
4. **管理员可直接开通**:给已有账号(不自动建号),来源记「控制台」。
5. **三条路共用同一套边界**:`checkGrantLimits`(行数、超时、有效期)与 `ensureBizQueryRole`(补业务查询角色、
   不给服务账号和停用账号)。网关内不能修改由仍启用的外部系统下发的授权 —— 否则外部系统从此既列不出也撤不掉它。
6. 业务方撤回申请另开 `POST /bizquery/apply/:id/cancel`:审批单的撤回接口挂在终端菜单下,业务方没有那个菜单。

## 后果

- 新装默认网关内申请。原来依赖 SRD 默认链接的部署,升级后要在设置里改为「外部审批系统」并填上申请页地址。
- 可申请的实例列表不按申请人的标签过滤(申请本来就是为了拿到还没有的访问权),但只暴露名称、引擎、环境。
- 批准与生成授权不在同一个事务里:预检之后、写入之前的一瞬间情况变了时,单子是批准的而授权没生成,原因记在
  申请上并通知申请人(状态 `failed`,通知类型 `exec-failed`,与"通过了的工单执行失败"同类,不按驳回归类,#180),
  需要重新申请。
