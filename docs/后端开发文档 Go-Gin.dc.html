03 核心架构:网关代执行

Gateway Proxy

所有命令不直连数据库,统一经网关:鉴权 → 风险判定 → (放行执行 / 拦截审批) → 审计留痕 → Webhook 外推。审批通过后由网关用实例的服务账号代执行。

func (g *Gateway) Execute(ctx, req ExecReq) (*ExecResult, error) {
  conn := g.conns.Get(req.ConnectionID)
  verdict := g.risk.Evaluate(ctx.User, conn, req.SQL)   // 三层判定
  switch verdict.Action {
  case ActionDeny:
     g.audit.Record(ctx, req, RiskHigh, ResultRejected); return nil, ErrForbidden
  case ActionApprove:
     ap := g.approval.Create(ctx, conn, req.SQL, verdict)  // 生成审批单 + Lark + 告警
     g.audit.Record(ctx, req, verdict.Risk, ResultPending)
     return &ExecResult{Intercepted: true, ApprovalNo: ap.No}, nil
  default: // ActionAllow
     res := g.driver(conn.Engine).Run(ctx, conn, req.SQL)  // 代执行
     g.audit.Record(ctx, req, verdict.Risk, ResultExecuted)
     return res, nil
  }
}

04 风险判定引擎(三层)

Risk Engine

判定顺序:① 菜单权限 → ② 能力矩阵(角色 × 能力 × 环境) → ③ 高危命令字典(环境 × 命令),叠加严格模式(无 WHERE 的 DELETE/UPDATE)。取最严档位。

func (e *RiskEngine) Evaluate(u User, c Conn, sql string) Verdict {
  verb := parseVerb(sql)                          // DROP / SELECT / ...
  cap  := mapVerbToCapability(verb)               // 能力维度
  if e.matrix.Level(u.RoleID, cap, c.Env) == Deny { return Verdict{Action: ActionDeny} }
  lvl := e.dict.Level(verb, c.Env)                // high / mid / off
  if e.strict && noWhere(sql, verb) { lvl = LevelHigh }
  switch lvl {
    case LevelHigh: return Verdict{Action: ActionApprove, Risk: RiskHigh, Rule: "高危DDL"}
    case LevelMid:  return Verdict{Action: ActionApprove, Risk: RiskMid}
    default:      return Verdict{Action: ActionAllow, Risk: RiskLow}
  }
}

07 审批、Lark 集成与告警

Approval & Lark
  • 创建审批单生成 ap_no 与审批步骤(按角色默认审批链),并落 audit_id。
  • 调用飞书开放平台审批/消息卡片 API,继承审批卡格式;同步告警至 #dba-oncall 与值班人。
  • 审批超时按设置:自动驳回 / 自动升级 / 保持等待(定时任务扫描 tbl_approval_step)。
  • 全部通过后回调网关代执行;任一拒绝即终止并审计。

08 审计与 Webhook 外推

Audit & Webhook

审计 append-only,每条记录 hash = SHA256(prev_hash + payload) 形成哈希链,防篡改。Webhook 推送以 HMAC-SHA256 签名,失败按指数退避重试。

sig := hmacSHA256(cfg.Secret, body)            // X-Vela-Signature
req.Header.Set("X-Vela-Signature", sig)
for i := 0; i < cfg.RetryMax; i++ {
   if ok := post(cfg.Endpoint, body); ok { break }
   time.Sleep(backoff(i))                       // 2^i 秒
}

09 MySQL 数据库设计

Schema (DDL)

命名规范:表名 tbl_ 前缀、主键约束 pk_ 前缀、索引 idx_ 前缀;不使用物理外键,关联约束由应用层(service/repository)维护。字符集 utf8mb4 / InnoDB,时间统一 DATETIME(3),枚举用 ENUM。

用户与角色

CREATE TABLE tbl_role (
  id           BIGINT       NOT NULL AUTO_INCREMENT,
  code         VARCHAR(64)  NOT NULL,               -- admin/owner/l2/ro/audit
  name         VARCHAR(64)  NOT NULL,
  layer        VARCHAR(32)  NOT NULL,               -- L0/L1/L2/L3
  description  VARCHAR(255),
  default_conn_role VARCHAR(64),
  created_at   DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  CONSTRAINT pk_tbl_role PRIMARY KEY (id),
  UNIQUE KEY idx_role_code (code)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

CREATE TABLE tbl_user (
  id          BIGINT       NOT NULL AUTO_INCREMENT,
  name        VARCHAR(64)  NOT NULL,
  email       VARCHAR(128) NOT NULL,

  mfa_enabled TINYINT(1)   NOT NULL DEFAULT 0,
  created_at  DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  CONSTRAINT pk_tbl_user PRIMARY KEY (id),
  UNIQUE KEY idx_user_email (email),
  KEY idx_user_role (role_id)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

10 非功能与错误码

NFR & Error Codes
  • 性能:风险判定走内存/Redis 缓存的字典与矩阵,目标 < 20ms;审计异步落库不阻塞执行。
  • 安全:JWT + MFA + IP 允许列表;连接凭据加密存储;Webhook 签名校验。
  • 可用性:网关无状态多副本;字典/矩阵变更经缓存失效热生效。
  • 部署:Docker 镜像 + 配置中心;migrations 管理 schema。
code含义
0成功
40001参数错误
40100未登录 / Token 失效
40300无菜单/能力权限
42200命令被拦截,需审批(返回 ap_no)
50000服务器内部错误
