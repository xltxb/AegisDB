## 二、High 级发现（详细）

### H-1 · 异步执行通道判定原始串，只读角色可在 PROD 写库

- **严重度**：High
- **位置**：`internal/service/async_exec.go:52-55`；根因 `internal/gateway/risk.go:441`（空动词→select）；正确实现对照 `internal/service/gateway.go:119-123`
- **核实结论**：**确认**。代码自身注释即为铁证。

**机理**：同步 `Exec` 无条件先 `SplitStatements` 再 `strictestVerdict`，并在注释(ER3)中明确警告不可对原始串判定。而 `ExecAsync` 判的是**原始串**，仅当 `len(stmts) > 1` 才改用逐条判定：

```go
// async_exec.go:52-55
v := s.Engine.EvaluateFor(s.Repo.EffectiveRoleIDs(u), conn.Engine, tier, sql) // 判原始串
if stmts := sqlutil.SplitStatements(sql); len(stmts) > 1 {
    v = s.strictestVerdict(u, conn, stmts) // 只有多语句才拆
}
```

`SplitStatements` 的 `flush` 只收非空 trim 结果，前导 `;` 被丢弃：`SplitStatements(";UPDATE …")` → `["UPDATE …"]`，`len==1`，于是**保留对原始串的判定**。而 `verbRe = ^\s*([a-z_]+)` 无法匹配前导 `;` → `ParseVerb(";UPDATE …")=""` → `MapVerbToCapability("")="select"`。只读角色 select 在 prod=allow → `ActionAllow` → 入队 → `runAsyncJob` 以 `sc.ExecContext(ctx, job.SQL)` 执行**原始串**。种子高危字典不含 INSERT/UPDATE/CREATE，无兜底。

`risk.go:441` 注释原文：*"Do NOT judge raw terminal input against this mapping — a stray leading separator (";UPDATE …") parses to no verb and would be filed as a read (ER3). Service.Exec normalises via SplitStatements first"* —— `Exec` 照做了，`ExecAsync` 漏了。

**利用**：只读研发账号（有 terminal 菜单）对 `POST /api/v1/terminal/exec-async` 提交：
- `;UPDATE users SET is_admin=1`
- `/*x*/;INSERT INTO audit_bypass VALUES(1)`
- `;CREATE TABLE evil(...)`

后端在 PostgreSQL simple protocol / MySQL 上执行前导空语句后的写操作，**完全绕过能力矩阵**。

**修复**：`ExecAsync` 与 `Exec` 对齐，无条件拆分判定：
```go
stmts := sqlutil.SplitStatements(sql)
if len(stmts) == 0 { return s.execJudgedAsync(...) } // 空/纯注释
v := s.strictestVerdict(u, conn, stmts)
```
删除"仅 len>1 才拆分"分支。

### H-2 · `SET @@GLOBAL.` 绕过会话作用域识别，只读角色可改服务器全局变量

- **严重度**：High（实战可达性取决于下游 DB 账号是否具 SUPER/SYSTEM_VARIABLES_ADMIN；网关连接账号通常高权）
- **位置**：`internal/gateway/session_scope.go:37`；短路点 `internal/gateway/risk.go:637-650`
- **核实结论**：**确认**。同步 `Exec` 与异步路径均成立。

**机理**：`SessionScoped` 把匹配 `^\s*SET\b` 但不在逃逸清单的语句当作"仅本会话"，短路后**只需 select 能力，跳过字典与严格模式**。逃逸正则：

```go
setEscapesSessionRe = regexp.MustCompile(`(?is)^\s*SET\s+(GLOBAL|PERSIST|PERSIST_ONLY|PASSWORD|ROLE|SESSION\s+AUTHORIZATION)\b`)
```

只认关键字形式 `SET GLOBAL`，不认 MySQL 等价的 `SET @@GLOBAL.var` 形式。`SET @@GLOBAL.read_only=0` 里 `SET` 后紧跟 `@@` → 逃逸不匹配 → `SessionScoped=true` → 仅 select 闸（ro=allow）→ 放行下发，修改**整个服务器**配置。

**利用**（payload）：
- `SET @@GLOBAL.read_only = 0`（关全局只读保护）
- `SET @@GLOBAL.sql_log_bin = 0`（关 binlog 掩盖写入）
- `SET @@global.super_read_only = 0`

**修复**：逃逸正则增加 `@@` 作用域识别，如追加 `SET\s+@@\s*(GLOBAL|PERSIST(_ONLY)?)\s*\.`；更稳妥改为**白名单会话作用域**（仅明确的 `SET [SESSION|LOCAL] var` / `SET @user_var` / `SET NAMES` / `SET search_path` 放宽，其余含任何 `@@global/@@persist` 一律走原判定）。

## 三、Medium 级发现

### M-1 · 外部审批回调可终审任意待审工单
- **位置**：`service/external_approval.go:126`（TaskID 交叉校验条件）、`:140`（自审批依赖回调方自填 approver）、`handler/admin.go:468`（`?secret=` 查询回退）
- **核实**：确认（攻击面 4、5 双代理独立命中）。`VerifyExternalCallback` 门禁为 enabled + 非空 secret + 恒时比较 + IP 白名单（默认空=任意来源）。`DecideApprovalExternal` 按可预测的 ApNo 关联；TaskID 交叉校验仅 `if ap.ExternalTaskID != "" && cb.TaskID != ""` 才做——**省略 task_id 即跳过**，未外发的工单也可被回调批准；自审批 SoD 依赖 `cb.Approver`，攻击者随意填绕过两人控制。
- **前提**：启用外部审批 + 持有 callbackSecret（供应商侧泄露 / `?secret=` 落代理日志 / 弱 secret 暴破，端点无限流）
- **修复**：仅接受 `ExternalTaskID!=""` 的工单并强制 TaskID 匹配；回调 approver 映射为网关用户并要求属该单审批链；改 HMAC(时间戳+body) 签名、去掉 `?secret=`；默认要求 callbackAllowIPs + 端点限流。

### M-2 · 已批准工单执行时不复核实例访问权/维护态/MFA/tier
- **位置**：`service/approval_execute.go:32-85`（缺 `canAccessConn`/`conn.Status`/`checkMFA`）、`:51`（复判用快照 `ap.TierCode`）
- **核实**：确认（攻击面 2、4 双代理命中）。approved 工单无过期（`SweepApprovalTimeouts` 只清 pending）；发起人权限/tag 被收窄、实例进 maint、MFA 被重置后仍可 execute。流水线 `stageExecute` 用实时 `tierCodeOf(conn)`，两路径不一致。
- **修复**：执行前 `canAccessConn` + maint 拒绝 + RequireMFA tier 要求 mfaCode；复判改用 `tierCodeOf(conn)`（解析失败即拒绝）；增加 approved 工单执行时限。

### M-3 · 流水线 backup/verify 模板 SQL 不过风险引擎
- **位置**：`service/pipeline.go:693`（`backupVerbs={CREATE,INSERT,SELECT}`）、`:698-733`、`:727`（审计归因 creator）
- **核实**：确认。有动词白名单（拒 DROP/DELETE/ALTER/GRANT），但白名单粒度粗：`CREATE USER/TRIGGER/PROCEDURE`、`INSERT...SELECT`、`SELECT...INTO OUTFILE`(verb=SELECT，且无 export 路径的 `writesFileRe` 兜底) 均可通过，且**完全不经 `Engine.EvaluateFor`/能力矩阵/字典/strict**（注释自认"the one execution channel that never meets the risk engine"）。审批人在工单看不到这些语句，审计 actor 记为发布创建者。
- **前提**：需 admin 配置流水线模板。
- **修复**：backup/verify SQL 运行时同样调 `Engine.EvaluateFor`；白名单细化为 `CREATE TABLE...AS SELECT`/`INSERT...SELECT` 并拒 `INTO OUTFILE/DUMPFILE`；审计 actor 记模板 CreatedBy。

### M-4 · 不存在的角色 id 被 RBAC 读作全放行 + 不限 tag（fail-open）
- **位置**：`repository/repository.go:262`（查无行→`LevelAllow`）、`:496`（无 tag→unrestricted）、`gateway/risk.go:558`（union 取最宽松）；触发入口 `handler/admin.go:280` AddMember 不校验角色存在、`service/admin.go:537,558` PATCH users 单角色路径漏 `validateRoleIDs`
- **核实**：确认。DB 查询出错时正确 fail-closed(ED3)，但"无行=allow"语义下，幽灵角色 id 使该用户所有 cell 读作 allow、tag 不受限。
- **前提**：需 admin 误操作/前端 bug 写入不存在的角色 id。
- **修复**：`AddMember`/`PatchUser(RoleID)` 调 `validateRoleIDs`；`EffectiveRoleIDs` 过滤不存在的 id；根本上 `capabilityLevelUnion` 对"某角色该 tier 无任何 capability 行"按 deny 处理。

### M-5 · API 凭据可绑定任意人类账号（含 admin）
- **位置**：`service/openapi.go:155-159`（Create 只查 Status 不查 Kind）、`:242-246`（Update 可换绑任意 user）；`middleware/apiclient.go:76-89` 注入 ctxUser
- **核实**：确认（双代理命中）。模型注释称"服务账号是 API 凭据唯一主体"，但 API 层未强制 `Kind==service`。可把机器凭据绑到真人 admin，以其身份走 `/open/*`，审计归属混淆。
- **修复**：Create/Update 校验 `Kind==service && Status==active`；禁服务账号持 admin/owner/audit；`APIClientAuth` 二次校验。

### M-6 · MFA grace 按用户代次缓存，被盗 token 可搭便车绕 PROD step-up
- **位置**：`service/service.go:353-355`（`mfaGraceKey=uid:tokenVersion:connID`）、`gateway.go:876-883`
- **核实**：确认。`TokenVersion` 用户级共享，注释称"bound to the session"与实现不符。受害者完成一次 step-up 后 30min（默认，上限 720）内，被盗 token 对同实例免 TOTP 执行 PROD。
- **修复**：JWT 加 `jti`，grace key 改 `uid:jti:connID`。

### M-7 · 凭据脱敏正则遗漏，明文口令进审计链/webhook/飞书
- **位置**：`pkg/sqlutil/redact.go:64,75,96`
- **核实**：确认（静态推演）。`CHANGE MASTER TO MASTER_PASSWORD='x'`（`_password` 前非词边界不匹配）、PG `CREATE SUBSCRIPTION ... CONNECTION 'host=h password=secret'`（conninfo 内未加引号不匹配）、DWS `SECRET_ACCESS_KEY 'sk'`（无规则）均漏脱敏，明文经 `appendAudit`(哈希链锁定不可改)/webhook/飞书卡片外发。
- **修复**：补 `master/source_password=`、conninfo `password=\S+`、`secret_access_key` 规则 + 通用键值兜底。

### M-8 · 自助 MFA setup/enable/disable 无口令重认证 + 零审计
- **位置**：`service/gateway.go:917-977`（无 recordAudit）、`handler/admin.go:542-579`
- **核实**：确认。盗 token 者可对未启用 MFA 账号 setup+enable 劫持其因子（把受害者锁出），或对已启用账号 disable，且审计链零痕迹（而管理员侧 mfa.reset/bind 有审计）。
- **修复**：三者要求携带当前口令(bcrypt 校验)；均 recordAudit；enable/disable 后 BumpTokenVersion。

### M-9 · 脚本上传/扫描无大小上限 → OOM DoS
- **位置**：`handler/terminal.go:213-241`（L220 `make([]byte, file.Size)`）、`:278-300`（L291 同）
- **核实**：确认。任何 terminal 用户上传数 GB 文件一次性分配全量内存；JSON `Content` 同样无界。对比 `handler/openapi.go:30` 开放接口有 15MB 上限，控制台路径反而无限制。
- **修复**：`fh.Size>max` 拒绝 + `io.LimitReader`；路由层 `MaxBytesReader`。

### M-10 · 敏感字段脱敏可子查询别名绕过（含导出）
- **位置**：`gateway/sensitive.go:55-120`（SensitiveMaskTargets）、`:213`（mentionsColumn）
- **核实**：确认（绕过）。`SELECT x FROM (SELECT id_card AS x FROM t_user) s` 选择列表项 `x` 不"提及" id_card → 不打码；走 `/export`(不勾 includeSensitive) 得原值 CSV，绕过"敏感导出需审批"控制。基于正则的列映射无法穿透子查询/CTE/UNION。
- **修复**：含子查询/派生表/UNION 且命中敏感表的查询，导出一律要求审批或拒绝；或用真实 SQL 解析器做列血缘。

### M-11 · 审计写入 fail-open
- **位置**：`service/service.go:174-234`（appendAudit 重试 5 次后仅 slog.Error 返回）、`external_approval.go:144`、`model.go:580`（Operator size:128）
- **核实**：确认。回调传入 >128 字节 operator 在 STRICT MySQL 下 INSERT 报错，审批已生效而审计链缺行。任何审计 INSERT 失败都不回滚/阻断动作。
- **修复**：`clip(operator,128)`；高危路径审计失败应 fail-closed 或写失败告警队列。

## 五、已核查、未发现问题的关键子面

- **JWT**：强制 `*SigningMethodHMAC`，`alg=none`/RS→HS 混淆不可行；claims 中角色/菜单不被授权逻辑信任（全部 DB 实时读）
- **同步 Exec 堆叠查询**：无条件 SplitStatements + strictestVerdict，前导分隔符、`SELECT 1;UPDATE` 均逐条拦
- **命令注入**：全仓无 `os/exec` 子进程，sqlplus/psql/mysql 均纯 Go 文本改写；对象浏览参数化 + 标识符白名单
- **DSN 注入**：库名字符集限制，MySQL 显式 `AllowMultiStatements=false`
- **IDOR**：uploads/snippets/async-jobs/export/审批执行/发布单均校验 owner==当前用户
- **MenuGuard/AdminOnly**：fail-closed（无 RoleMenu 行或 DB 出错均 403）
- **出站 SSRF**：解析期 LookupIP + 拨号期按已解析 IP 复检(防 DNS rebinding)，覆盖 loopback/private/link-local/元数据；禁重定向（仅提示 Azure 168.63.129.16 未拦）
- **连接密码**：AES-256-GCM 随机 nonce；`json:"-"`；访问日志脱敏
- **导出下载**：Abs + 前缀校验 + 仅匹配本人任务精确路径
- **审批执行 TOCTOU/重复**：`status=approved AND executed_at IS NULL` 原子 claim；脚本 SHA-256 复核
- **自审批**：默认阻断发起人；`allowSelfApprove` 仅 admin 可改
- **服务账号身份边界**：Login/设密拒绝 kind=service；审批链排除服务账号
