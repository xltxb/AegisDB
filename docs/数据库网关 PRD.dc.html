01 背景与目标

Background & Goals

1.1 问题背景

生产数据库的直连操作长期存在三类风险:其一,高危命令(DROP / TRUNCATE / DELETE / ALTER / RENAME 等)一旦误执行即造成不可逆数据损失;其二,权限粗放,研发与运维共用账号、缺乏分层管控;其三,操作散落在各类客户端,无统一审计,事后难以追溯。本系统以"网关代理 + 分层策略 + 审批前置 + 全量审计"解决上述问题。

1.2 产品目标

  • 统一入口:所有数据库操作收敛到 Web 命令行,经网关代理执行,不再直连。
  • 分层管控:按环境(PROD / STAGING / DEV)与角色分层,差异化决定命令是放行、审批还是拦截。
  • 高危前置审批:命中高危命令自动生成审批单,继承飞书(Lark)审批卡并同步告警,通过后由网关代执行。
  • 全量可审计:每条命令(含被拦截、被拒绝的)均不可篡改留痕,支持筛选、导出与 Webhook 实时外推。

1.3 范围与非目标

本期范围:连接配置、分层与角色权限、高危命令规则、Web 命令行、SQL 脚本上传扫描、审批流、审计与 Webhook、系统设置、中英双语。

非目标(本期不做):可视化建表 / ER 图、查询结果图表分析、数据脱敏导出、SQL 性能优化建议、多租户计费。

02 角色与权限分层模型

Roles & Layered Authorization

系统采用三层授权模型,自上而下逐级收紧,任一层拒绝即终止:

LAYER 1
菜单权限
角色能进入哪些功能菜单(终端、审批、配置、审计…)。
LAYER 2
能力矩阵
该角色在各环境对各能力的权限:允许 / 需审批 / 禁止。
LAYER 3
高危命令字典
命令级:按环境对具体命令配置拦截 / 审批 / 放行。

2.1 内置角色

角色分层职责与默认授权
平台管理员L0 · 全局管理连接配置、规则、用户与系统设置;可审批高危命令。全菜单开放。
DBA 负责人L1 · 终审高危命令审批链终审节点;可在 PROD 执行全部能力(经审批)。
DBA L2L2 · 执行可在 PROD 执行常规操作,高危命令需走审批;不可改权限与系统设置。
研发只读L3 · 只读仅 Web 命令行查询与审计日志;PROD 只读、DEV 可写。
审计员L3 · 审计仅审计日志查看与导出;不可执行任何数据库操作。

2.2 环境分层策略

环境默认策略高危命令处理
PROD 生产strict默认拦截,高危命令必须二级审批后由网关代执行。
STAGING 预发approve-1高危命令仅需一级审批。
DEV 测试audit-only自由执行,仅记录审计,不拦截。
需求 ID需求描述优先级
FR-RBAC-01系统提供可配置的角色,每个角色拥有独立的菜单权限、能力矩阵与成员列表。P0
FR-RBAC-02授权按"菜单 → 能力矩阵 → 命令字典"三层逐级生效,任一层拒绝即终止操作。P0
FR-RBAC-03能力矩阵支持按环境(PROD/STAGING/DEV)分别设定:允许 / 需审批 / 禁止三态。P0

03 功能需求

Functional Requirements

3.1 Web 命令行终端

三栏 IDE 工作台:左侧为按环境分层的数据库树(实例 → 库 → 表),中间为命令行执行区,右侧为执行上下文与风险检查面板。用户输入 SQL 回车执行,网关实时判定风险等级。

需求 ID需求描述优先级
FR-TERM-01左侧树按环境分组展示实例 / 数据库 / 表,实例标注风险等级(高危 / 受限),支持搜索定位。P0
FR-TERM-02命令行区回显历史(信息 / 命令 / 输出 / 成功 / 拦截),支持 SELECT 类查询返回行数与耗时。P0
FR-TERM-03输入即时按当前连接环境与高危字典判定:命中高危命令在终端内嵌"已拦截"提示并转入审批。P0
FR-TERM-04右侧上下文面板展示目标实例、库、连接角色、网关策略、受限命令清单(PROD)与审批链。P1
FR-TERM-05底部状态栏显示连接状态、角色、策略、编码与审计开关。P2

3.2 高危命令拦截与审批流

命中高危命令时弹出居中审批提交卡,强制填写操作原因、确认审批链,提交后生成审批单并同步告警。审批人在"审批待办"中通过 / 拒绝,通过后由网关代执行。

需求 ID需求描述优先级
FR-APPR-01识别高危命令:命中字典中标记为"拦截/审批"的命令,或开启严格模式时无 WHERE 的 DELETE/UPDATE。P0
FR-APPR-02提交卡展示待执行命令、环境、实例、风险标签(不可逆/锁表),并强制填写操作原因(必填)。P0
FR-APPR-03生成审批单(含审批单号、审计 ID),继承飞书(Lark)审批卡格式,并同步告警至 #dba-oncall 与值班负责人。P0
FR-APPR-04审批待办页支持"待我审批 / 全部",卡片展示命令、发起人、目标、原因与审批链,可通过 / 拒绝并即时反馈状态。P0
FR-APPR-05审批链支持多级(发起 → 组长 → 负责人),并可配置审批超时处理(自动驳回 / 自动升级 / 保持等待)。P1

3.3 SQL 脚本上传与预执行扫描

用户可上传 .sql 脚本,系统在执行前自动按高危字典扫描:拆分语句、剔除注释、逐条判定风险,并出具扫描报告。若检出高危语句,整脚本须提交审批后由网关代执行;全部安全则可直接执行。

需求 ID需求描述优先级
FR-SQL-01支持上传 .sql 文件,读取内容并按 ; 拆分为独立语句,自动剔除行注释与块注释。P0
FR-SQL-02逐条语句按当前环境的高危字典判定风险等级(高危 / 需审批 / 安全),无 WHERE 的 DELETE/UPDATE 单独标记。P0
FR-SQL-03扫描报告展示统计概览(总语句 / 高危 / 需审批 / 安全)与逐条明细及风险标签。P0
FR-SQL-04检出高危/需审批语句时,执行入口变为"提交审批后执行";全部安全时可直接执行并在终端回显结果。P0
FR-SQL-05扫描规则与终端实时拦截、高危字典完全一致;字典调整后扫描结果同步变化。P1

3.4 数据库连接配置

后台管理所有数据库实例,按环境分层展示,统一经网关代理执行。支持新建连接并设定引擎、环境、网关策略。

需求 ID需求描述优先级
FR-CONN-01连接列表按 PROD/STAGING/DEV 分组,展示实例名、分层、引擎、地址、默认角色、网关策略与状态。P0
FR-CONN-02新建连接表单:实例名、地址端口、引擎、分层环境、网关策略;保存即"测试连接并接入网关"。P0
FR-CONN-03支持的引擎:MySQL、PostgreSQL、ClickHouse、Redis、TiDB(可扩展)。P1
FR-CONN-04实例状态可在"在线 / 维护"间切换,维护态下提示拦截或限制操作。P2

3.5 高危命令规则配置

高危命令字典按环境独立配置,每个命令在各环境下可设为拦截 / 审批 / 放行。PROD 配置直接驱动终端与脚本扫描的拦截判定。规则可新增、移除,触发命令可自定义。

需求 ID需求描述优先级
FR-RULE-01高危字典内置 DROP、TRUNCATE、DELETE、ALTER、RENAME、GRANT、REVOKE 等命令,可新增自定义命令。P0
FR-RULE-02每个命令按环境(PROD/STAGING/DEV)分别配置三态:拦截 / 审批 / 放行,可点击循环切换。P0
FR-RULE-03规则即时生效:PROD 字典调整后,终端实时拦截与脚本扫描结果同步变化。P0
FR-RULE-04新建规则支持自定义触发命令(可勾选已有命令并输入任意命令)、适用环境、命中动作与审批链。P1
FR-RULE-05严格模式开关:开启后拦截无 WHERE 的 DELETE / UPDATE。P1

04 高危命令拦截流程

Interception Flow
1 · 用户下发命令
DBA 在 Web 命令行输入 SQL,或上传 .sql 脚本。
2 · 网关风险判定
按"菜单权限 → 能力矩阵 → 高危字典(当前环境)"逐层校验,确定放行 / 审批 / 拦截。
3 · 命中高危 → 拦截 + 生成审批单
终端内嵌拦截提示;弹出提交卡,用户填写原因并确认审批链。生成审批单与审计 ID,继承 Lark 审批卡,同步告警至 #dba-oncall。
4 · 审批人决策
审批人在待办中通过 / 拒绝;超时按设置自动驳回或升级。
5 · 网关代执行 + 全量审计
通过后由网关代执行并回显结果;无论放行 / 拦截 / 拒绝,均不可篡改留痕并可经 Webhook 外推。

06 非功能需求

Non-functional Requirements
类别要求
安全强制 MFA(生产)、IP 允许列表、会话有效期与空闲锁定;审计日志不可篡改;Webhook 负载 HMAC-SHA256 签名。
性能命令风险判定为同步前置,目标增加延迟 < 20ms;审计写入异步不阻塞执行。
可用性网关多实例无状态部署;策略与字典变更热生效,无需重启会话。
可观测审计可导出,可经 Webhook 外推 SIEM;投递失败自动重试并记录成功率。
合规所有生产高危操作可追溯到人、命令、原因与审批链。

07 关键验收标准

Acceptance Criteria
  • 在 PROD 输入 DROP TABLE 必被拦截并生成审批单,审批通过前不执行。
  • 同一命令在 DEV(放行)直接执行、在 PROD(拦截)进入审批,体现环境分层差异。
  • 上传含高危语句的脚本,扫描报告准确统计高危条数,且整脚本须审批后才执行。
  • 高危字典在 PROD 调整后,终端与脚本扫描的判定即时同步变化。
  • 每条命令(含被拒绝)均可在审计中检索,并能导出与经 Webhook 推送。
  • 无菜单权限的角色看不到对应功能入口。
