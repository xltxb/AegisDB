# IM 渠道审批与通知 · 启用手册

网关直接对接 IM 平台:审批卡片**私信**给审批链上已绑定该渠道的成员,点按钮即可通过 / 驳回;
群通知把新工单推到指定群。设计见 ADR 0020 与
`docs/superpowers/specs/2026-09-27-im-channel-approval-design.md`。

- 审批**通过不执行命令**(ADR 0010):通过后由发起人回到「审批」页执行。
- 站内审批始终可用。多个渠道可同时开,任一渠道(或控制台)的决定生效,其余卡片自动收起。
- 这些都是**运行时设置**(存库、在「设置 › IM 渠道」里配),不是部署期环境变量。保存即生效,
  不需要重启。

## 当前支持

| 渠道 | 群通知 | 交互审批 |
|---|---|---|
| 飞书 | ✅ 自定义机器人 webhook | ✅ 开放平台应用(长连接 / webhook) |
| Telegram | 规划中(第 6 期) | ✅ long polling / webhook |
| 钉钉 | 规划中 | 规划中(第 4 期) |
| Slack | 规划中 | 规划中(第 5 期) |
| 企业微信 | 规划中 | 不支持(平台群机器人无回调) |

## 飞书群通知

1. 飞书群 › 设置 › 群机器人 › 添加「自定义机器人」,复制 webhook 地址;需要签名校验时同时开启
   「签名校验」并复制密钥。
2. 网关「设置 › IM 渠道」:
   - 「控制台外网地址」填审批人能打开的网关地址,卡片里「前往审批」按钮用它拼链接。
   - 飞书卡片打开「群通知」,填 webhook 与签名密钥,点「发一条测试通知」。
3. 保存。此后每张新审批单(终端高危命令、执行窗口申请、含敏感字段的导出、发布单审批阶段)都会
   往群里推一张卡片。卡片里的命令已脱敏(口令替换为 `***`)。

签名密钥加密落库、接口不回显;输入框留空保存表示保持原值。

群通知是异步发送的:某次发送失败时,「设置 › IM 渠道」该渠道的状态标签显示「群通知失败:<原因>」
(同时记一条 WARN 日志),下一次发送成功后自动恢复。

## 飞书交互审批

1. 飞书开发者后台(国际版 Lark 同理)› 创建**企业自建应用**,在「添加应用能力」里打开**机器人**。
2. 「权限管理」开通:`im:message`(以应用身份发消息)、`im:message.p2p_msg:readonly`(读取用户发给机器人的单聊消息)。
   发布一个版本,让权限生效,并把「可用范围」设成需要审批的人。
3. 「事件与回调」:
   - **长连接(推荐)**:订阅方式选「使用长连接接收事件 / 回调」;添加事件 `im.message.receive_v1`,
     添加回调 `card.action.trigger`。网关主动连飞书,不需要公网入口,多实例部署也安全(飞书把每个事件只投给
     其中一个连接)。
   - **webhook**:先在网关「设置 › IM 渠道」填好「回调根地址」;把 `<回调根地址>/api/v1/im/lark/webhook`
     同时填进「事件配置」与「回调配置」的请求地址;在「加密策略」里设置 Encrypt Key,并记下同一页的
     Verification Token。网关只收加密且签名正确的请求,其余一律 403。
   - 只订阅 `im.message.receive_v1` 事件与 `card.action.trigger` 回调。订阅了其他事件,网关不处理,
     会回错误,飞书可能因此反复重投。
4. 网关「设置 › IM 渠道 › 飞书」打开「交互审批」,填 App ID、App Secret,选版本(飞书 / Lark)与接收方式;
   webhook 模式再填 Encrypt Key 与 Verification Token。私有化部署在「开放平台地址」里填自己的地址。保存。
   「开放平台地址」与其他出站地址走同一套校验(必须是 https 且不能指向内网),所以私有化部署的开放平台
   需要能以公网式 https 地址访问;仅在开发用的内网出站目标开关打开时才放行内网地址。
5. 状态显示「运行中」且没有错误提示即已连通。App Secret 错、应用没开机器人能力、开放平台地址填错时,状态会
   显示飞书返回的错误码与原因。
6. 卡片里的「通过 / 驳回」只做决定,不执行;决定后所有渠道上的这张单的卡片都会收起,收起后的卡片只保留单号和
   结果,详情在控制台。

## Telegram 交互审批

1. 在 Telegram 里找 **@BotFather**,`/newbot` 建一个机器人,拿到 bot token。
2. 网关「设置 › IM 渠道 › Telegram」:填 Bot Token,打开「交互审批」,选接收方式:
   - **Long polling(默认)**:网关主动去 Telegram 取事件,内网部署也能用,不需要公网入口。
     **同一时刻只允许一个网关实例** —— 第二个实例会与它互相踢掉(Telegram 返回 409)。
   - **Webhook**:Telegram 把事件推到网关。需要在「回调根地址」填一个 Telegram 能访问到的
     公网 HTTPS 地址,并设置 webhook secret(需 32 位以上字母、数字、`_` 或 `-`);网关保存后会自动调用 `setWebhook` 登记
     `<回调根地址>/api/v1/im/telegram/webhook`。多实例部署用这个模式。可以在「回调来源 IP
     白名单」里填 Telegram 的出口网段(官方公布为 `149.154.160.0/20`、`91.108.4.0/22`)。
   关闭交互审批后,Telegram 侧的 webhook 登记仍然保留,推送会被网关以 403 拒绝;切回 polling 模式时网关会自动删除它,也可以手动调用 `deleteWebhook` 清理。
3. 保存后看渠道状态:token 或配置错误(如 401/404、setWebhook 被拒)会让状态显示错误原因;「运行中」且无错误提示才表示已连通。
4. 自建了 Bot API server 的,把「Bot API 地址」改成它的地址,其余不变。

**绑定**:每个审批人在头像菜单「IM 账号绑定」里点 Telegram 的「绑定」,拿到绑定码后,
用**自己的** Telegram 私聊机器人,先发 `/start`,再把绑定码发过去。机器人回复「已绑定到 …」
即完成。管理员代绑需要对方的 Telegram **数字** user id(可以让对方私聊 @userinfobot 查看),
不是 @用户名。

**审批**:建单后,审批链上已绑定 Telegram 的成员(发起人本人除外)会收到一张卡片,点
「✅ 通过」或「❌ 驳回」。结果由按钮上方的提示告诉点击者;工单一结束(无论在哪里决定),
所有人手上的卡片按钮都会换成一颗显示结果的按钮。

**安全**:点击只认绑定表 —— 群里转发了卡片、陌生人点了按钮,都会被拒绝并写审计。bot token
与 webhook secret 加密落库、不回显;任何错误信息里的 token 都会被替换成 `<bot-token>`。

## 交互审批的账号绑定

审批卡片上的点击只认**绑定过的账号**。每个人在每个渠道绑定一次:

1. 头像菜单 › 「IM 账号绑定」,在对应渠道点「绑定」,弹出一串 `BIND-XXXXXXXX`(10 分钟有效,只显示一次)。
2. 用**自己的** IM 账号私聊对应渠道的机器人,发送这串码。机器人回复「已绑定到 张三(zhang@…)」即完成。
   飞书里在搜索框搜机器人的名字(绑定弹窗里显示的那个)打开单聊。

管理员可在「权限 › 用户详情 › IM 绑定」里代绑或解绑(换号、离职回收、绑错时用),两个动作都写审计。

点击卡片时:

- 没绑定、账户停用、服务账号 → 拒绝,且审计里记一行「有人试过」。
- 不在审批链上、自己发起的单(未开「允许自审」)、角色没有「审批」菜单 → 拒绝,提示与控制台完全一致。
- 已被别人处理 → 发起人与链成员看到当前状态,不会重复决策;其他人(以及不存在的单号)只得到
  「仅审批链成员可处理该工单」。

IM 审批**不受控制台来源 IP 白名单约束**:点击来自 IM 平台,不经过浏览器访问网关的那条路。IM
平台是一个网络之外的入口,由管理员在「设置 › IM 渠道」里显式打开;不希望有这个入口,就不要打开
交互审批。

## 从审批魔方升级

- 审批魔方对接已整体删除:回调端点 `/api/v1/approvals/lark/callback` 不再存在,`approval.external.*`
  设置(含加密的令牌与回调密钥)由迁移 `0007` 删除。
- **升级前**请在审批魔方侧清空待审单:升级后那些飞书卡片点击无效,只能回控制台处理。
- 原「设置 › 通知」里的飞书群通知配置由迁移 `0006` 自动搬到「设置 › IM 渠道 › 飞书」,行为不变。
- 迁移会删列,不能与旧版本进程共存。按 README 顺序:备份 → 停旧进程 → migrate → 起新进程。
