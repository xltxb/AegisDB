# AI 巡检报告接入说明

给对接 AI 巡检系统的同事看:AI 每巡检完一个实例,就把报告推送到网关;网关按实例归档、永久保留,DBA 在网关的「巡检报告」页里查看。

需求与设计见 `.scratch/inspection-report/PRD.md`。

## 一、网关侧准备(平台管理员做一次)

1. **配置保存路径**:管理后台 → 系统设置 → 网关 → 「巡检报告保存路径」,填一个网关服务器上的目录(例如 `/var/vela/inspection`),保存。
   - 报告压缩后按 `实例名/年/日期.html.gz` 存在这个目录下,**永久保留**。按每份压缩后约 100KB 估算,91 个集群每年约 3.3GB。
   - 不配置时,上传接口会拒绝(错误码 42602)。
2. **建服务账号**:管理后台 → 系统设置 → 开放接口 → 服务账号,新建一个(例如「AI 巡检系统」),角色给「研发只读」即可 —— 上传报告只看凭据的范围,不看账号角色。
   - 开放接口凭据不能绑在平台管理员身上(平台会拒绝),所以要单独建服务账号。
3. **签发凭据**:同一页「开放接口凭据」→ 新建,绑定上面的服务账号,**权限范围只勾 `inspection:write`**;知道 AI 系统的出口 IP 的话,填进 IP 白名单。
   - 签发后页面只显示一次完整凭据(`<key>.<secret>`),交给 AI 系统保管。
   - `inspection:write` 只能上传巡检报告,做不了别的任何事。

## 二、接口

```
POST {网关地址}/api/v1/open/inspection-reports
Authorization: Bearer <key>.<secret>
Content-Type: application/json
```

也可以用 `X-Vela-Key: <key>` + `X-Vela-Secret: <secret>` 两个请求头代替 `Authorization`。

### 请求体

```json
{
  "instance": "prod-c66-gi",
  "date": "2026-10-15",
  "inspectedAt": "2026-10-15T03:12:00+08:00",
  "score": 86,
  "level": "warning",
  "counts": { "critical": 1, "warning": 3, "info": 5 },
  "findings": [
    { "severity": "critical", "category": "分区", "title": "t_order 分区 2027-12-31 后用尽",
      "object": "gli_c66_gi.t_order", "detail": "最后一个分区上界 2028-01-01,需要补分区" }
  ],
  "html": "<!doctype html>……完整报告……"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `instance` | 是 | 网关里的**实例名**(与网关「实例管理」里的名字完全一致,区分大小写) |
| `date` | 是 | 巡检日期 `YYYY-MM-DD`,不能晚于明天 |
| `inspectedAt` | 否 | 巡检完成时间,RFC 3339 格式 |
| `score` | 否 | 健康分 0–100 |
| `level` | 是 | 总体结论:`ok` / `warning` / `critical` |
| `counts` | 否 | 各级问题数,不能为负 |
| `findings` | 否 | 问题列表,最多 500 条;每条 `severity`(critical / warning / info)和 `title` 必填 |
| `html` | 是 | 完整报告 HTML。可以带内联脚本和样式(网关在沙箱里显示),不要引用外部资源 |

请求体总大小上限 **20MB**。

**同一实例、同一天再传一次会覆盖**之前那份(返回 `replaced: true`),AI 重跑不会产生重复报告。

### 返回

成功:`{"code": 0, "msg": "ok", "data": {"id": 123, "replaced": false}}`

HTTP 状态码都是 200,看信封里的 `code`:

| code | 含义 | AI 侧怎么处理 |
|---|---|---|
| 0 | 成功 | — |
| 40400 | 网关里没有这个实例名 | **不要重试**,核对实例名(信息里带着传上来的名字) |
| 40001 | 字段不合法 | **不要重试**,看 `msg` 里是哪个字段 |
| 41300 | 超过 20MB | 不要重试,精简报告 |
| 40100 / 40300 | 凭据无效 / 没有 `inspection:write` 范围 / 来源 IP 不在凭据白名单 | 不要重试,找网关管理员核对凭据 |
| 42602 | 网关还没配置巡检报告保存路径 | 不要重试,找网关管理员配置 |
| 50000 或网络错误 | 网关内部错误 / 连不上 | 指数退避重试 3 次(例如 10s、30s、90s) |

## 三、示例

HTML 要作为 JSON 字符串放进请求体(换行、引号都要转义),所以先用脚本拼出请求体,再发送。

**Python(推荐)**

```python
import json, requests

with open("prod-c66-gi.html", encoding="utf-8") as f:
    html = f.read()

body = {
    "instance": "prod-c66-gi",
    "date": "2026-10-15",
    "level": "warning",
    "score": 86,
    "counts": {"critical": 0, "warning": 2, "info": 4},
    "findings": [{"severity": "warning", "category": "索引", "title": "t_user 缺少联合索引"}],
    "html": html,
}
r = requests.post(
    "https://gateway.example.com/api/v1/open/inspection-reports",
    headers={"Authorization": "Bearer <key>.<secret>"},
    json=body, timeout=60,
)
print(r.json())   # {'code': 0, 'msg': 'ok', 'data': {'id': 123, 'replaced': False}}
```

**curl + jq**

```bash
jq -n --rawfile html prod-c66-gi.html \
  '{instance: "prod-c66-gi", date: "2026-10-15", level: "warning", score: 86,
    counts: {critical: 0, warning: 2, info: 4}, html: $html}' > body.json

curl -s -X POST https://gateway.example.com/api/v1/open/inspection-reports \
  -H 'Authorization: Bearer <key>.<secret>' \
  -H 'Content-Type: application/json' \
  --data-binary @body.json
```

## 四、在网关里看报告

- 用户后台 → 「巡检」:每个实例最近一份报告,严重和警告的排在前面,并标出今天还没收到报告的实例;点进去看历史,再点一份看完整报告。
- 管理后台 → 管理总览 → 「今日巡检」:今天有严重 / 警告问题的实例,以及今天没收到报告的实例。
- 终端左侧实例树、实例管理页:最近一份报告是严重 / 警告的实例,名字旁有标记,点一下打开报告。
- 能看报告的是平台管理员、DBA 负责人、DBA L2,能看全部实例。每次打开报告都记审计。
